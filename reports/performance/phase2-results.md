# v5.12.5 후속 성능 검증 결과

측정일: 2026-09-29. 컴퓨터 종료 전에 구현·검증을 완료했고, 재개 후 저장된 최종 측정의 소스 SHA-256과 현재 소스가 일치함을 확인했다. 재개 과정에서 탐색이나 벤치마크를 반복하지 않았다.

## 버전과 범위

- 작업 전: 5.12.4 / 작업 후: 5.12.5
- 사용자 실행 파일: `outputs/omok.html` (outputs 내 HTML은 이 파일 하나)
- 기존 빌드 산출물 `dist/index.html`도 표준 빌드로 갱신했다.
- 규칙, UI 구성, 자체 proof 연구, DFPN, Rapfi는 변경하지 않았다. commit/push는 하지 않았다.
- 측정 환경: Intel Core i5-4460, 논리 CPU 4개, headless Edge 154.0.4258.37.
- 기준/최종 측정 각각 10개 고정 위치 × 6모드 × 3회 = 180건. 실제 브라우저 Worker 실행 경로를 사용했다. 외부 게임과 동시 실행하는 부하는 재현하지 않았다.

## 1 Worker와 2 Worker

독립적인 후보별 상대 응수 검색을 동일한 3초 벽시계 한도로 비교했다. 같은 전체 트리를 중복 검색한 것이 아니다. 완성된 2 Worker UI 추천기의 비교는 아니며, 후보 반박 검색 작업의 비교다. 후보가 하나인 경우 실제 Worker는 하나였다.

6수 위치의 두 후보 검색, 3회 중앙값:

| 항목 | 1 Worker | 2 Worker |
|---|---:|---:|
| 소요 시간 | 2,783.7ms | 2,825.3ms |
| nodes/s | 21,007 | 45,359 |
| 후보별 완료 깊이 | 3 / 3 | 4 / 4 |
| 메인 스레드 지연 p95 | 1.2ms | 1.5ms |
| 관측 최대 지연 | 2.3ms | 157.1ms |

quiet-middle의 소요 시간은 2,167.9→2,775.1ms, wide-middle은 1,534.1→2,816.1ms였다. 짧은 전술 검사에서 두 후보 작업의 중앙값은 176.7→160.6ms로 절감 폭이 작았다. 취소 동작도 두 구성에서 확인했다. 취소 API 시간과 후속 메시지 유무를 검사했으며 OS 스레드의 실제 종료 시각을 측정한 것은 아니다.

**최종 선택: 1 Worker 유지.** 무거운 독립 검색의 처리량 이득은 있으나 전체 지연과 응답성의 무악화를 확인하지 못했다. 관측된 최대 지연 한 건만으로 일반적인 인과관계를 단정하지 않는다.

## 25초 모드

기존 약 15초 후보 비교 및 최대 세 후보의 제한된 전술 검사를 유지했다. 남은 시간을 항상 소진하는 방식은 채택하지 않았다.

세 복잡한 위치 × 3회에서 기존 최종 후보에 상대 분석을 최대 8초 추가했다. 이는 별도 실행 실험이므로 이전 시간과 합산한 값을 통합 실행 시간으로 보지 않는다.

- 9건 모두 상대 강제승리 반박은 발견되지 않았다.
- 6수 위치: 추가 검색 중앙값 약 7.247초, 상대 F7, depth 5, 미증명. 일률적인 추가 검색을 채택할 근거가 없었다.
- quiet-middle: 약 0.578초, 높은 절댓값의 평가가 나왔지만 미증명 상태를 유지했다.
- wide-middle: 약 0.121초, M9 뒤 상대의 196개 합법 방어 모두 패배로 판정되었다.

마지막 신호는 기존 certificate verifier로 제한된 단일 호출을 수행해 독립 확인했다. 결과는 `verified:true`, 방어 196개, VCF 196개, 1,633ms였다. 기존 verifier의 흑 선공 입력에 맞춰 색을 교환했으며 규칙은 양측 대칭이다.

**적용 정책:** 최종 후보가 승리에 가까운 큰 양의 평가를 갖고 여유 시간이 있을 때만 기존 상대 분석을 최대 1.5초 수행한다. 평가값은 검사 대상 선택에만 사용한다. 완결된 기존 판정 및 합법 PV가 있을 때만 증명 상태로 승격하며, 미완료 검색은 미증명으로 유지한다.

최종 통합 측정에서 wide-middle/25초 모드의 M9은 3회 모두 검증된 승리로 반환되었다. 추가 확인 시간은 70.1 / 62.2 / 105.4ms, 전체 시간은 10,472.2 / 10,466.3 / 10,514.3ms였다. 대표 합법 수순은 `M9 K7 L9 N9 I6`이다. 대표 PV 자체가 모든 방어의 증명이라는 뜻은 아니며, 위 196개 방어 검사가 근거다.

**품질 개선: YES — 해당 위치의 증명 상태 정확도 개선.** 일반적인 승률·기력 상승까지 검증한 것은 아니다.

## 자동 종료

기존 완료 여부·동일 최선수·점수 안정성 조건에 다음을 추가했다.

1. 최근 세 완료 깊이가 연속이어야 한다.
2. 첫 세 수의 PV와 후보 순위가 일치해야 한다.
3. 1·2위 점수 차가 충분하고 안정적이어야 한다.
4. PV 등 이력이 빠져 있으면 안정으로 간주하지 않는다.
5. 자동 모드는 큰 평가값 하나만으로 종료하지 않는다. 기존 검증된 승패·필수 단일 응수의 조기 반환은 유지한다.

이 변경은 기존 Reader 자동 종료 경로를 강화한다. 복잡한 위치의 기존 심층 단계 전체를 새로운 안정성 스케줄러로 교체한 것은 아니다.

합성 완료 이력 9개 진단에서 잘못된 안정 판정은 5건→0건이 됐다. 실제 게임 패배 9건을 재현한 테스트라는 의미는 아니다.

| 자동 모드 고정 그룹 | 기준 평균 | 최종 평균 |
|---|---:|---:|
| 쉬운 위치 3개 × 3회 | 71.2ms | 54.1ms |
| 복잡한 위치 3개 × 3회 | 13,378.0ms | 12,586.7ms |

실행 조건의 변동이 있어 위 차이를 전부 코드 개선에 의한 속도 상승으로 해석하지 않는다.
