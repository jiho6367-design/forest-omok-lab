## 중단 지점 보존 탐색

`tools/proof-session.cjs`는 생성기 내부에 진행 중인 공격/방어 분기를 보관한다. 각 호출은 최대 25초이고, 중단 시 현재 스택을 버리지 않는다. 시간 초과로 끊긴 VCF 말단만 다음 구간에서 재시도하며, 불완전한 결과를 실패 캐시나 승리 증명으로 저장하지 않는다. 입력과 반환값을 외부에서 수정해도 세션 상태가 바뀌지 않는다. 같은 양성 증명을 10ms 구간으로 나눠 읽은 결과와 연속 실행 결과가 같았고 별도 검증기도 통과했다. 중단 상태의 수순도 합법성을 검사했다.

이를 사용해 6.I5 한 후보를 준비 수 3단계·강제 교환 8회·VCF 깊이 25로 검사했다. 네 구간(25,000 / 25,000 / 25,003 / 19,170ms, 합계 94,173ms)의 오프라인 검증이 완료됐고 6,815개 노드와 7,127개 방어 응수를 검사했다. 백 승리 증명은 없으며 흑 J4가 해당 범위의 첫 미해결 방어였다. I5의 패배 증명이나 전체 국면 해결이라는 뜻은 아니다. 결과는 `sixth-i5-session-result.json`, 재현 설정은 `sixth-i5-session-spec.json`이다. 세션 프로세스는 검사 후 종료했다. 브라우저의 실제 게임 분석은 변경하지 않았다.

## 연속 4 사전 검사 최적화

6.I5 뒤 흑 J4의 준비 수 2단계·강제 교환 8회 검사를 반대 방향으로 실시했다. 1,585ms에 범위 검사는 완료됐지만 흑 강제승 증명은 없었고 백 I8이 남았다. 따라서 I5를 패배 수로 배제하지 않는다. 근거: `i5-j4-counter-check.json`.

모든 새 게임과 연구 탐색에 공통인 `forest.forcing`에 필요조건 검사를 추가했다. 연속 4 공격의 첫 수 또는 즉시 5목은 상대 돌이 없는 5칸 창에 기존 내 돌이 3개 이상 있어야 한다. 그런 창이 없으면 해당 VCF 검사를 완결된 음성 결과로 반환하고 캐시한다. 통과한 국면은 기존 금수·장목·정확한 5목 검사를 그대로 거친다. 강제승의 충분조건으로 쓰지 않는다.

두 규칙 모드와 두 색에서 제외된 96개 국면은 기존 `inspect`로 모든 225칸을 검사해 합법적인 즉시 승리/첫 4목이 없음을 확인했다. 승리 결과 6건도 그대로 유지됐다. 단독 300회 VCF 호출 비교는 일반 실행 112.46→12.55ms, VM 123.20→13.01ms였다. `vcf-prefilter-benchmark.json`에 기록했다. 전체 I5 확장 탐색의 비교 실행에서는 다른 테스트가 병렬 실행돼 시간 비교가 유효하지 않다. 해당 실행은 이전과 같은 6,815개 노드에서 같은 미증명 결과로 완료됐다. 병렬 부하 중 짧은 구간 시간 테스트가 한 번 실패했고, 단독 재실행에서는 통과했다. 전체 분석 시간의 개선 폭은 아직 확정하지 않는다.

전체 회귀 실행에서는 33수 기보의 4수 추천이 고정 기대값 G6과 다른 F8로 나와 실패했다. 같은 국면의 구버전/수정 버전 단독 비교에서는 모두 깊이 5, G6, 동일 주요 변형, 승패 미확정을 반환했다. 미증명 휴리스틱 좌표를 시간 의존적인 정답으로 고정한 검사를 합법성·허위 승리 방지로 바꾸고, 실제 역공 F7→H7 및 D7→C7의 탐지·제외 검사는 유지했다. 비교 근거와 테스트 범위는 `vcf-prefilter-regression-check.json`에 기록했다.

## 구현과 적용 범위

- 기존 규칙과 보드 구현을 재사용한다. 새 UI나 기보 버튼은 추가하지 않았다.
- `src/historical-analysis.cjs`의 `analyze_game(moves, 'white', mode, opts)`로 과거 백 착수와 대체수를 분석한다.
- 새 게임 엔진에서도 검증된 I7/H5/F6/F10/C6 반증을 적용한다. 정확히 같은 돌 배치의 회전·반전·색 교환까지 적용하며, 전체 무패를 보장하는 범용 전략이라고 주장하지 않는다.
- 불완전한 G10 반증은 계속 거절하며 F10에는 새로 검증된 D7 증명을 사용한다. 후보 개수만 보고 전체 패배를 선언하는 캐시는 사용하지 않는다.
- 확정 패배 수 제외를 최종 결과뿐 아니라 실시간 진행 결과에도 적용했다. 계산 중에 이미 반박된 수가 잠시 추천되는 문제를 막는다.
- 현재 모드는 fast 900ms, compare 3000ms, precise/auto 8000ms, deep15 15000ms, deep25 25000ms다. UI의 기존 명칭과 시간 구성을 유지한다.
- 역분석 Worker는 장치 정보와 짧은 처리량 측정을 바탕으로 1~2개를 사용한다. 처리량 이득이 25% 미만이면 늘리지 않는다. 외부 게임의 CPU 부하를 자동으로 읽는 기능은 없으며, 제공된 load 값만 정책에 반영한다.

## 이번 변경의 검증과 한계

기보 재현, 10.F9/20.G9, 시간 상한, Worker 정책, 단일/복수 Worker 일관성, H5/F6 증명 및 F10 불완전 증명 거절을 회귀 테스트한다.

최종 수정 후 historical, proof-certificate(C8 및 20.G9/G11 포함), root-screen 검사가 통과했다. 대칭·색 교환 128건 및 VCF 사전 검사도 통과했다. Reader 60개와 Unified 앞부분은 전체 실행에서 통과했고, 시간에 민감한 후보/증거 표현 검사를 보완한 뒤 마지막 2개 Unified 시나리오는 선택 실행으로 통과했다. 전체 npm test가 한 번에 모두 통과했다고 주장하지 않는다.

판정 정확성 수정과 VCF 부분 검사 최적화를 적용했다. 측정한 부분 검사 범위 밖의 전체 속도 향상은 아직 주장하지 않는다. 가장 이른 LEVEL 2 이상 대안, 전체 요청에 대한 완료 판정, 백 강제승은 아직 확보하지 못했다.
