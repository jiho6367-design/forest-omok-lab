# 22수 백 패배 기보 검증 상태 — v5.12.4

## 기보 분석

v5.12.4에서 18.C8 및 20.G9·G11의 이미 증명된 반증을 새 게임 추천과 역분석 API에 연결했다. 별도 증명 검증은 각각 611/203/203개 방어 응수를 통과했다. 20.G9를 미증명 방어 후보 LEVEL 1로 남기던 누락을 LEVEL 0으로 수정했다. 같은 국면의 회전·반전·색 교환에도 적용되지만, 다른 모든 국면의 승리를 보장하는 패턴이라는 뜻은 아니다.

최초의 결정적 실수와 LEVEL 2 이상 대안은 아직 증명하지 못했다. 아래 결과를 백의 필승 또는 무패 증명으로 해석하면 안 된다.

현재까지 가장 이른 **실제 착수의 강제패 증명은 6.I7**이다. 흑 E8 이후 모든 백 응수를 반박하는 `i7-loss-certificate.json`이 독립 검증을 통과했다. 따라서 원래 기보의 6.I7을 유지한 채 8수 이후만 바꿔 백의 강제승을 찾을 수는 없다. 6수 또는 그 이전의 대안을 찾아야 한다. 6수 직전 백의 승리 가능성은 아직 증명되지 않았으므로 이를 최초의 결정적 실수라고 확정하지 않는다.

6수의 상위 대안 I5·G9·J4는 흑 준비 수 두 단계와 VCF depth 25 검사에서 반박되지 않았다(각 7,251 / 6,710 / 7,505ms, 제한 범위 검사 완료). 이 결과는 백의 무패나 승리를 증명하지 않는다. 25초 상한의 역분석 API를 실제 실행한 결과는 6.I7 → I5, LEVEL 1, 주요 후보 수순 I5–G8–I8이며 6,790ms에 반환됐다. 근거는 `sixth-move-candidate-check.json`과 `current-api-result.json`이다. 새로운 필승 패턴으로 등록하지 않았다.

추가 검증에서 I5–G8–I8 뒤 흑의 준비 수 두 단계 강제승은 발견되지 않았다(8,064ms). I5–G8 뒤 백의 같은 범위 강제승도 발견되지 않았다(5,679ms). 4수 직전 H8–G7–G6 국면의 백 공격 검사도 같은 범위에서 증명을 찾지 못했다(3,881ms). 모두 범위 내 검사는 완료됐으며, 미증명을 무패 또는 승리 불가능으로 확대하지 않는다. 근거: `i5-g8-followup-check.json`.

연구 도구에 `--forcing-extensions`를 추가했다. 강제 4/방어 교환은 준비 수 깊이를 차감하지 않고 별도 8회 상한 안에서 읽으며, 각 방어의 합법성과 상대 즉시 승리를 계속 검사한다. I5–G8 국면에서 준비 수 두 단계에 강제 교환을 확장한 검사는 22,863ms에 완료됐고 백 강제승은 없었다. 강제 교환 262건, 방어 응수 23,262건을 확인했다. `test:forcing-extensions`는 깊이 0에서도 강제 교환이 검사되는지, 상대 즉시 승리를 무시하지 않는지, 시간 초과를 증명으로 채택하지 않는지 확인한다. 브라우저 엔진에는 아직 적용하지 않았다. 근거: `forcing-extension-check.json`.

연구 도구도 게임 엔진의 검증된 패배 수 목록을 재사용하도록 연결했다. 그전에는 6.I7의 승리 증명을 불필요하게 다시 탐색했다. 이제 후보별 상태(`certified_loss` / `unproved` / `incomplete`)와 증명이 막힌 상대 응수를 기록한다. 6수 전체 25초 검사에서는 I7을 제외했고, I5·J4의 미해결 상대 응수는 K3, G8은 E4, G9는 E8이었다. I6에서 시간 초과했으므로 전체 후보 완료가 아니다. `unproved`는 상대 강제승 증명이 아니라 해당 범위에서 내 강제승을 못 찾았다는 뜻이다. 근거: `sixth-root-extension-check.json`. 다음 검증은 이 미해결 응수에서 이어가야 하며 동일한 전체 탐색을 처음부터 반복하지 않는다.

I5–K3 국면을 이어 검사했으나 25,008ms에서 미완료로 종료됐고 승리 증명은 없었다. G8을 우선 검사하자 전술 점수가 같은 응수가 좌표순으로 정렬되어 I1이 먼저 나타났다. 이를 최선 응수로 해석하지 않도록, 연구 탐색의 루트 응수 순서에 기존 평가 함수의 제한된 보조 점수를 추가했다. 모든 합법 응수 검사는 유지한다. 같은 G8 후보의 우선 응수는 G9로 바뀌었으며, I5–K3–G8–G9 국면의 확장 공격 검사도 25,002ms에서 미완료로 끝났다. 백 강제승은 아직 미증명이다. `i5-k3-extension-check.json`과 `i5-k3-g8-g9-check.json`에 정확한 후보별 상태를 저장했다. 상대 즉시 승리·시간 초과·확정 패배 수 제외 회귀 검사는 통과했다.

연구 도구에 `--root-moves`를 추가해 미완료였던 F9만 검사했다. 3,813ms에 지정 범위 검사가 완료됐지만 흑 H10 뒤 백의 승리 증명은 없었다. 전체 국면이나 모든 첫 수를 검사 완료했다는 뜻은 아니다. `i5-continuation-f9-check.json`에 선택 범위와 결과를 기록했다. 선택 밖의 즉시 승리 수가 반환되지 않는지, 선택된 강제승이 독립 검증을 통과하는지, 불법·점유 좌표가 거절되는지 테스트했다. 미검증 수의 필승 등록이나 브라우저 추천 변경은 없다.

## 6수 후보 범위 검사 완료

### 6.H7와 기존 증명의 적용 범위

E6–I6 뒤 J6 검사의 기존 세션은 25초 29구간(725,000ms)까지 미완료였다. 상대가 다음에 둘 차례인 후보 국면에서 연속 4 강제승을 최대 20ms로 먼저 검사하는 선택 가지치기 `counterVcfPruning`을 연구 세션에 추가했다. 증명이 있을 때만 제외하고 시간 초과/미증명은 원래 탐색으로 돌아가므로 불완전한 반증을 패배 판정으로 쓰지 않는다. 내 즉시 5목은 먼저 인정한다.

같은 J6 설정으로 새 방식을 실행하니 1,185ms에 지정 범위가 완료됐고, 흑 G8이 남아 백 강제승 증명은 없었다(`fourth-f7-j6-counter-prune-check.json`). 별도 감사 실행에서 제외한 334개 반증을 모두 독립 검증해 7,184ms에 통과했다(`fourth-f7-j6-counter-audit.json`, `fourth-f7-j6-counter-audit-result.json`). 기존 세션은 같은 범위가 새 방식으로 완료된 것을 확인한 뒤 종료했다. 기존 최종 스냅샷은 당시 미완료 상태를 유지한다. 이 측정은 특정 오프라인 증명 탐색이며 브라우저 전체 속도 향상 수치가 아니다.

`test/proof-counter-vcf.cjs`는 패배 후보 제외의 독립 증명, 양성 승리 증명 보존, 내 즉시 승리 우선순위를 확인한다. 기존 proof-session, defense-extensions, proof-immediate-pruning도 통과했다. 연구 옵션은 기본 꺼짐이며 브라우저 추천은 변경하지 않았다.

4.F7 계열에서 남은 E6/I6 방어의 강제 후속 수를 확인했다. E6–흑 I6 뒤 백 J6, I6–흑 E6 뒤 백 D6가 각각 유일한 즉시 패배 방어였다. 두 국면 각각 합법 백 착수 212개를 전수 확인했다(`fourth-f7-e6-i6-mandatory.json`). 최초 단회 검사는 모두 25초 미완료였으며 그 파일은 당시 관찰 기록으로 유지한다. J6는 위의 개선 검사로 완료했고, D6도 같은 준비 수 2단계·강제 교환 8회 범위를 상대 VCF 가지치기로 2,677ms에 완료했다. D6의 남은 흑 응수는 G5이며 백 승리는 미증명이다. 제외한 209개 반증은 독립 검증에서 모두 통과했다(`fourth-f7-d6-counter-check.json`, `fourth-f7-d6-counter-audit-result.json`). 필수 방어라는 사실을 전체 무패나 승리로 확대하지 않았다.

4수 직전의 후보 생성 범위 48개도 준비 수 2단계·강제 교환 8회로 검사 완료했다(`fourth-all-counter-session-result.json`, 25,000+5,257ms). 강제 확장은 발생하지 않았고 승리 증명은 없었다. 초반의 짧은 공격 검사이며 모든 합법 착수나 게임 전체를 해결한 결과가 아니다.

6.H7은 준비 수 3단계·강제 교환 8회 검사에서 2,850ms에 범위 완료됐지만 흑 G8이 남았다(`sixth-h7-counter-session-result.json`). 이 조건부 국면에서 합법 백 착수 218개를 모두 검사했다. 216개에는 흑의 연속 4 승리 증명이 있었고 각각 독립 검증을 통과했다. 반증되지 않은 수는 8.E8과 8.I8뿐이다(`sixth-h7-g8-all-legal-screen.json`). 이는 두 수의 무패/승리 증명이 아니다. 백 준비 수 2단계 검사에서도 두 수는 각각 흑 I8/D8 응수가 남았다. 두 백 수 뒤 흑 준비 수 2단계·강제 교환 8회 검사는 각각 25초에 미완료다(`sixth-h7-g8-e8-black-check.json`, `sixth-h7-g8-i8-black-check.json`). E8 뒤 흑 J8/I8/F7은 이 범위에서 증명이 없고 G9 분기가 미완료였으며, I8 뒤 흑 E8은 증명이 없고 D8 분기가 미완료였다. 단회 프로세스는 종료돼 이 두 JSON은 재개 상태가 아니다. 새 승리 추천이나 브라우저 변경은 하지 않았다.

4.F7–H7–F5–H6–H9–H4 뒤 백 H5는 준비 수 2단계·강제 방어 확장 검사에서 11,382ms에 지정 범위 완료됐지만 흑 F6가 남았다(`fourth-f7-h9-h4-h5-white-check.json`). 이어 F6 뒤 합법 백 착수 214개를 흑 VCF 깊이 19로 전수 검사해 212개를 반박했고 E6/I6만 남았다. 119ms, 미완료/미방문 없음이며 전체 무패 증명은 아니다(`fourth-f7-after-f6-screen.json`). E6/I6의 별도 백 공격 검사는 11,191ms에 지정 범위 완료됐지만 각각 흑 I6/E6가 남았다(`fourth-f7-e6-i6-white-check.json`). 다음 검증은 이 두 방어 수에서 이어가며 이미 반박된 212개를 반복하지 않는다. 아직 새 게임에 필승 수를 추가할 근거는 없다.

4.F7–H7–F5–H6 뒤 백 H9/H5/F6을 검사했다. 25초 시점에 F6/H9는 각각 흑 H4가 남았고 H5 분기는 미완료였다(`fourth-f7-f5-h6-white-check.json`). 이어 F6 착수 후 상대 VCF를 직접 확인해 흑 H5의 강제승을 발견했고 독립 검증기에서 모든 합법 백 방어 216개가 반박됐다(`fourth-f7-f6-direct-refutation.json`). 재사용 역분석 API도 해당 F6을 LEVEL 0으로 분류함을 확인했다(`fourth-f7-f6-api-check.json`). 이 특정 8.F6의 패배를 4.F7 자체의 패배로 확대하지 않는다. 엔진은 일반 연속 4 검사로 이미 이 반증을 처리하므로 별도 기보 전용 예외는 추가하지 않았다.

## 구현과 적용 범위

연구 검증기의 준비 수 한도가 0인 노드에서는 원래도 즉시 승리·4목·유일한 필수 방어만 확장한다. `horizonPruning`은 이 조건에서 확장할 수 없는 일반 후보를 위치 평가 전에 제외한다. 4목의 실제 합법 승리점 확인은 기존 solve 경로에 유지했다. `test/proof-horizon-pruning.cjs`에서 D6 음성 범위, 양성 F5 증명, 즉시 5목을 전후 비교해 증명 트리·루트 결과·노드·방어 수가 동일했다. D6 단독 비교는 3,057→1,107ms(144노드), 양성 F5는 880→821ms(215노드)였다. 전체 E8 탐색이나 브라우저의 가속 수치로 일반화하지 않는다. counter-VCF, defense-extensions, proof-session 회귀 검사도 통과했다.

기존 E8 세션은 17구간 425,000ms까지 미완료 상태로 보존했다. 최적화한 같은 범위의 E8 비교 세션도 8구간 200,000ms 시점에 미완료이며 흑 F7의 백 공격 후보를 검사 중이다(`h7-d8-e8-horizon-session-result.json`). 양쪽 모두 입력 대기 중이며 재실행 파일이 아닌 살아 있는 세션의 스택을 유지한다. 첫 세션은 시간 초과만을 이유로 폐기하지 않았다. 이번 변경은 연구 검증기에만 적용되고 게임 엔진에는 적용되지 않았다.

6.H7–G8–8.I8 뒤 미완료였던 흑 D8만 분리해 같은 준비 수 2단계·강제 교환 8회 범위를 검사했다. 12,608ms에 완료됐고 백 E8이 남아 흑 승리는 증명되지 않았다(`h7-i8-d8-session-result.json`). 이어서 백 E8의 승리 검사를 준비 수 3단계·강제 교환 8회로 시작했다. 열일곱 구간, 누적 425,000ms 시점에도 미완료이며 첫 흑 F7 응수 안을 탐색 중이다(`h7-d8-e8-white-session-result.json`). 상대 VCF 보조 검사 6회가 시간 상한에 걸렸지만 이는 가지치기 없이 원래 탐색으로 돌아가는 경로이며 증명으로 사용하지 않았다. 이 결과를 백 무패나 승리로 해석하지 않는다. 백 검사 프로세스는 입력 대기 상태로 유지하며 스택을 보존했다. 파일 자체는 재개용 체크포인트가 아니다. 브라우저 코드·25초 예산·추천은 변경하지 않았다.

- 기존 규칙과 보드 구현을 재사용한다. 새 UI나 기보 버튼은 추가하지 않았다.

- 새 게임 엔진에서도 검증된 I7/H5/F6/F10/C6 반증을 적용한다. 정확히 같은 돌 배치의 회전·반전·색 교환까지 적용하며, 전체 무패를 보장하는 범용 전략이라고 주장하지 않는다.
- 불완전한 G10 반증은 계속 거절하며 F10에는 새로 검증된 D7 증명을 사용한다. 후보 개수만 보고 전체 패배를 선언하는 캐시는 사용하지 않는다.
- 확정 패배 수 제외를 최종 결과뿐 아니라 실시간 진행 결과에도 적용했다. 계산 중에 이미 반박된 수가 잠시 추천되는 문제를 막는다.
- 현재 모드는 fast 900ms, compare 3000ms, precise/auto 8000ms, deep15 15000ms, deep25 25000ms다. UI의 기존 명칭과 시간 구성을 유지한다.
- 역분석 Worker는 장치 정보와 짧은 처리량 측정을 바탕으로 1~2개를 사용한다. 처리량 이득이 25% 미만이면 늘리지 않는다. 외부 게임의 CPU 부하를 자동으로 읽는 기능은 없으며, 제공된 load 값만 정책에 반영한다.

## 최신 검증 상태: E8 두 시점 구분

8.I8–D8 뒤 10.E8의 준비 수 3단계·강제 교환 8회 검사가 최적화 세션 11구간, 합계 265,682ms에 범위 완료됐다. proof=null, searchComplete=true이며 남은 흑 응수는 F7이다(h7-d8-e8-horizon-session-result.json). 이는 백 패배 증명이 아니라 이 범위의 백 승리 미증명이다. 상대 VCF 보조 검사 15회 시간 초과는 제외 근거로 쓰지 않고 본 탐색으로 돌아갔다. 같은 범위를 완료한 뒤 최적화 세션과 425,000ms 시점에 미완료였던 구버전 세션을 모두 종료했다. 위의 입력 대기/보존 설명은 당시 상태이며 현재 두 세션 모두 종료됐다. 구버전 파일은 미완료 기록을 유지한다.
