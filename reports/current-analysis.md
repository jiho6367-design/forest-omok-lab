# 22수 백 패배 기보 검증 상태 — v5.12.3

## 기보 분석

최초의 결정적 실수와 LEVEL 2 이상 대안은 아직 증명하지 못했다. 아래 결과를 백의 필승 또는 무패 증명으로 해석하면 안 된다.

현재까지 가장 이른 **실제 착수의 강제패 증명은 6.I7**이다. 흑 E8 이후 모든 백 응수를 반박하는 `i7-loss-certificate.json`이 독립 검증을 통과했다. 따라서 원래 기보의 6.I7을 유지한 채 8수 이후만 바꿔 백의 강제승을 찾을 수는 없다. 6수 또는 그 이전의 대안을 찾아야 한다. 6수 직전 백의 승리 가능성은 아직 증명되지 않았으므로 이를 최초의 결정적 실수라고 확정하지 않는다.

6수의 상위 대안 I5·G9·J4는 흑 준비 수 두 단계와 VCF depth 25 검사에서 반박되지 않았다(각 7,251 / 6,710 / 7,505ms, 제한 범위 검사 완료). 이 결과는 백의 무패나 승리를 증명하지 않는다. 25초 상한의 역분석 API를 실제 실행한 결과는 6.I7 → I5, LEVEL 1, 주요 후보 수순 I5–G8–I8이며 6,790ms에 반환됐다. 근거는 `sixth-move-candidate-check.json`과 `current-api-result.json`이다. 새로운 필승 패턴으로 등록하지 않았다.

추가 검증에서 I5–G8–I8 뒤 흑의 준비 수 두 단계 강제승은 발견되지 않았다(8,064ms). I5–G8 뒤 백의 같은 범위 강제승도 발견되지 않았다(5,679ms). 4수 직전 H8–G7–G6 국면의 백 공격 검사도 같은 범위에서 증명을 찾지 못했다(3,881ms). 모두 범위 내 검사는 완료됐으며, 미증명을 무패 또는 승리 불가능으로 확대하지 않는다. 근거: `i5-g8-followup-check.json`.

연구 도구에 `--forcing-extensions`를 추가했다. 강제 4/방어 교환은 준비 수 깊이를 차감하지 않고 별도 8회 상한 안에서 읽으며, 각 방어의 합법성과 상대 즉시 승리를 계속 검사한다. I5–G8 국면에서 준비 수 두 단계에 강제 교환을 확장한 검사는 22,863ms에 완료됐고 백 강제승은 없었다. 강제 교환 262건, 방어 응수 23,262건을 확인했다. `test:forcing-extensions`는 깊이 0에서도 강제 교환이 검사되는지, 상대 즉시 승리를 무시하지 않는지, 시간 초과를 증명으로 채택하지 않는지 확인한다. 브라우저 엔진에는 아직 적용하지 않았다. 근거: `forcing-extension-check.json`.

`f10-proof-audit.json`은 **성공한 증명 파일이 아니다**. 검증기가 반드시 거절해야 하는 불완전한 수순과 미해결 분기를 기록한다. `h5-loss-certificate.json`, `f6-loss-certificate.json`은 별도 검증기를 통과한 모든 방어 응수 증명이다.

새 F10 증명은 25초+22,931ms, 6.I7 전체 증명은 25초 검증 5회+1,008ms에 검증됐다. 이것은 오프라인 증명 검증 시간이며 실제 게임의 분석 시간 제한을 변경하지 않는다. 완료된 분기만 세션 내부에 보관하고, 시간 초과를 증명으로 채택하지 않는다. `npm run verify:opening`으로 재현할 수 있다.

`later-root-screen.json`은 14·16·18·20·22수의 모든 합법 후보를 빠짐없이 검사한 결과다(총 10,732ms, 미완료 후보 없음). 연속 4 공격에 반박되지 않은 후보는 각각 F6 / C6·G10 / G4·C8·G9·G11 / G9·G11 / 없음이다. 별도 심층 반증에 의해 C6과 C8도 패배로 확인됐으므로, 이 목록을 안전한 후보 목록으로 해석하지 않는다. 16수 직전 백 공격의 준비 수 두 단계 탐색은 13,107ms에 완료됐지만 강제승을 찾지 못했다. 이는 전체 게임의 무승리 증명이 아니다.

## 구현과 적용 범위

- 기존 규칙과 보드 구현을 재사용한다. 새 UI나 기보 버튼은 추가하지 않았다.
- `src/historical-analysis.cjs`의 `analyze_game(moves, 'white', mode, opts)`로 과거 백 착수와 대체수를 분석한다.
- 새 게임 엔진에서도 검증된 I7/H5/F6/F10/C6 반증을 적용한다. 정확히 같은 돌 배치의 회전·반전·색 교환까지 적용하며, 전체 무패를 보장하는 범용 전략이라고 주장하지 않는다.
- 불완전한 G10 반증은 계속 거절하며 F10에는 새로 검증된 D7 증명을 사용한다. 후보 개수만 보고 전체 패배를 선언하는 캐시는 사용하지 않는다.
- 확정 패배 수 제외를 최종 결과뿐 아니라 실시간 진행 결과에도 적용했다. 계산 중에 이미 반박된 수가 잠시 추천되는 문제를 막는다.
- 현재 모드는 fast 900ms, compare 3000ms, precise/auto 8000ms, deep15 15000ms, deep25 25000ms다. UI의 기존 명칭과 시간 구성을 유지한다.
- 역분석 Worker는 장치 정보와 짧은 처리량 측정을 바탕으로 1~2개를 사용한다. 처리량 이득이 25% 미만이면 늘리지 않는다. 외부 게임의 CPU 부하를 자동으로 읽는 기능은 없으며, 제공된 load 값만 정책에 반영한다.

## 이번 변경의 검증과 한계

기보 재현, 10.F9/20.G9, 시간 상한, Worker 정책, 단일/복수 Worker 일관성, H5/F6 증명 및 F10 불완전 증명 거절을 회귀 테스트한다.

이번 변경은 판정 정확성 수정이다. 계산 속도가 향상됐다는 주장은 하지 않는다. 가장 이른 LEVEL 2 이상 대안, 전체 요청에 대한 완료 판정, 백 강제승은 아직 확보하지 못했다.
