# 학습 저장 공간 보관 정책

2026-10-14 사용자 요청: 현재 실험을 유지하면서 불필요한 자료를 자동 정리하고, 학습 원본의 무제한 누적을 제한한다. 채택 모델과 검증 근거는 보존한다.

## 적용 범위와 기본값

새 연속 실험은 `storage-policy.json`을 생성한다. 기존 실험은 이 파일을 명시적으로 설치한 경우에만 새 정책을 사용한다. 기본값은 최근 **500,000개 샘플**, 원본 `dataset.jsonl` **1 GiB**, 파생 snapshot **최근 3회**다. 샘플 수와 바이트 수 중 먼저 도달하는 한도를 적용하며, JSONL 행 중간을 자르지 않는다. 최신 행은 원본 바이트 그대로 보관한다. 최종 시험의 특징·정답을 읽어 보관 순위를 결정하지 않는다.

학습 원본 한도는 재학습할 경험 풀의 정책이다. 기존 snapshot 선택·학습 알고리즘·채택 조건은 바꾸지 않는다. 원본 경험 풀이 바뀌면 이후 학습 결과가 달라질 수 있으며, 과거 경험 전체를 다시 학습할 수 있다고 주장하지 않는다. 현재 모델의 가중치와 채택 snapshot은 보존한다.

## 자동 정리 시점

- 원본 경험 풀: 검증과 채택/유지 판정이 끝난 **cycle-end**, 또는 쓰기가 없는 재개 시점의 **analyze** 단계에서만 정리한다. 진행 중인 검증·학습·자료 생성에서는 줄이지 않는다.
- snapshot: 기존 원자적 파생 자료 보관 규칙으로 최근 3회, 현재 cycle, 채택 모델 관련 자료를 보호한다. 보호 자료가 있으면 3회보다 많이 보관한다.
- 준비 캐시와 optimizer checkpoint: 현재·최근·채택 모델의 자료를 보호하고, 정해진 이름과 출처가 확인된 불필요한 자료만 정리한다. 알 수 없는 파일과 연결된 경로는 삭제하지 않는다.
- 완료된 가져오기의 `continuation.sqlite`: `families`의 정확한 split 조회와 원본 manifest를 유지한다. 가져오기 검증이 끝나고 다시 사용하지 않는 `positions`, `games`, `aliases`, `recovery_positions` 테이블만 제거하고 VACUUM한다. 미완료 가져오기는 정리하지 않는다.

한도는 안전한 단계 경계에서 적용하므로 한 cycle 동안 새로 생성한 자료가 일시적으로 더해질 수 있다. 기존 실험이 한도를 초과한 채 검증 중이면 그 검증을 마친 뒤 줄인다. 전체 디스크의 기존 예산은 별도로 유지하며, 증거가 예산을 초과하면 삭제를 강행하지 않고 저장 공간 사유로 중단한다.

## 반드시 남기는 자료

채택 모델, 가중치, 관련 snapshot/manifest/family sidecar, 검증 대국과 arena 결과, trial 예약과 판정 기록, 누적 노출·계보, 가족 split, 실제 대국 기록, journal의 ID/충돌 확인/누적 계수는 유지한다. 이전 실험이나 `.recycle`을 통째로 삭제하지 않는다. 현재 실행과 채택 검증에 사용한 파일은 해시를 대조해 보존한다.

이 때문에 **프로젝트 전체 용량이 영원히 일정해지는 정책은 아니다**. 큰 학습 원본과 재생성 가능한 자료의 증가는 제한하지만, 실제 대국·검증·노출 증거와 채택된 모델 자료는 계속 늘 수 있다. 18 GiB 전체 예산은 이 증거까지 포함한다.

## 중단 복구와 누적 계수

원본 교체는 `replay-retention-intent.json`에 교체 전후 SHA-256, 크기, 누적 샘플 수를 기록한 뒤 수행한다. 교체와 journal 커서 갱신 사이에서 프로세스가 종료돼도 같은 intent로 복구한다. 파일·커서가 예상과 다르면 정리를 거부한다. 실제 보관 행 수와 누적 생성 샘플 수는 별도로 유지한다. 과거 ID와 digest도 남으므로 재추가·충돌 검사는 유지된다. 다음 학습에 필요한 새 표본 수를 실제 보관 행 수로 오인하지 않는다.

`experience-retention.json`은 표시용 최신 요약, `experience-retention.jsonl`은 최근 100회 기록이다. 상세 정리 intent와 불변 snapshot manifest가 원본 증거 역할을 한다. 대시보드는 실제 확보한 용량과 보관 한도, 검증 종료까지 원본 정리를 미룬 상태를 표시한다.

보관된 실행기는 기존 과학적 코드와 식별자를 유지한 채 명시적인 host 저장 정책을 적용한다. 기존 검증 결과의 게시에는 정확한 코드 변경 SHA-256을 연결한 운영 호환성 영수증이 필요하다. 엔진·학습·검증 코드 변경을 이 영수증으로 허용하지 않는다.

## 검사

`node test/learning-experience-retention.cjs`는 작은 생성 fixture에서 바이트/행 한도, 증거 보존, 누적 계수, ID 충돌, 가져오기 가족 split, 실제 프로세스 종료 후 복구, 실행 중 작업 거부를 검사한다. 운영 실행 데이터는 CI fixture로 사용하지 않는다.
