# 채택 후보의 GitHub 게시 규칙

실험과 원본 학습 자료는 노트북에 보존한다. 오목용 일일 `github` 동기화는 새로 채택된 후보가 확인될 때만 후보 추론 산출물과 작은 검증 근거를 게시한다. 미채택·미완료 평가를 채택으로 표시하지 않는다. 별개 python-class 일요일 동기화는 변경하지 않는다.

## 게시 대상

`artifacts/adopted-models/<artifact-sha256>/`의 검증된 두 파일만 게시한다.

- `model.json`: 프로그램이 사용할 추론 구조·가중치. 대국, 데이터셋, optimizer와 체크포인트를 포함하지 않는다.
- `evidence.json`: 실행 ID, 평가와 게시의 코드 버전·해시, 재현 가능한 허용 설정, 비교 상대, 검증 대국 수·결과, 채택 기준과 실제 통과 여부, 원본 및 게시 산출물 해시.

게시 준비는 모델의 accepted 표지만 신뢰하지 않는다. 모델 산출물, 실행의 채택 기록, 동일 후보에 대한 완료된 검증 결과와 배포 근거를 교차 검증한다. 불일치·유실된 근거·원본 변경은 게시를 보류하고 보고한다. 원본 근거는 로컬에서 보존하며 공개 파일에는 개인 경로와 불필요한 원본 필드를 복사하지 않는다.

## 자동 게시

읽기 전용 확인:

`node tools/learning/sync-adoption.cjs`

사용자가 승인한 채택 후보 자동 게시:

`node tools/learning/sync-adoption.cjs --push`

새 채택이 없거나 이미 게시된 동일 산출물이면 업로드와 커밋을 건너뛴다. 새 채택을 게시할 때는 main의 작업 파일과 인덱스가 깨끗하고, 로컬 HEAD가 가져온 origin/main과 일치해야 한다. 다른 변경·미게시 커밋·원격 분기가 있으면 보류한다. 검증된 두 경로만 스테이징하고 커밋 전후 다시 확인한다. 대량 add, 강제 add, 강제 push, reset, stash, 로컬 자료 삭제를 사용하지 않는다. 게시 커밋 이후 통신 실패가 생기면 다음 실행에서 무조건 재작성하지 않고 상태를 확인해 보고한다.

전체 대국 데이터, 경험 DB, snapshot, optimizer 체크포인트, 미채택 후보, 캐시·임시 파일은 게시 대상이 아니다. `.gitignore`는 보조 장치이며, 자동 게시의 두 파일 허용 목록이 실제 경계를 결정한다.

## 유지보수 코드와 CI

사용자가 요청한 정책·CI·소스 유지보수 커밋은 채택 후보 게시와 별도 작업이다. 필요한 코드·테스트·문서만 검토해 올리고, 다른 작업자의 미완료 변경을 섞지 않는다.

일반 `npm test`와 `npm run test:learning`은 깨끗한 GitHub 체크아웃에서 작동한다. 과거 실행기 테스트는 추적된 코드와 작은 역사 실행기 fixture로 immutable archive를 자체 생성한다. 로컬 실험 파일이나 `work/runtime-archives`를 CI 입력으로 요구하지 않는다. 보존·동시 실행·초기 잠금·오류·identity 검증은 유지한다.

실제 로컬 아카이브의 추가 통합 검증은 명시적으로 실행한다:

`node test/learning-archived-retention.cjs --local-archive=<보존 archive JSON 절대 경로>`

`node test/learning-archive.cjs --local-baseline=<baseline JSON 절대 경로>`

이 선택적 검증을 위해 실제 학습 데이터를 GitHub에 올리지 않는다.

## 기존 자동화 프롬프트

기존 `github` 자동화의 폭넓은 로컬 변경 동기화 문구는 아래 문구로 교체한다. 기존 자동화 ID·주기·대상 대화는 유지하고 다른 자동화는 변경하지 않는다. 이 문서와 AGENTS.md 변경만으로 앱의 저장된 프롬프트가 바뀌는 것은 아니다.

> 숲속 오목 저장소에서 `node tools/learning/sync-adoption.cjs --push`를 실행한다. 새로 채택되고 근거 검증을 통과한 후보가 있을 때만 검증된 모델과 공개 근거 두 파일을 커밋·게시한다. 새 채택이 없으면 모든 커밋·업로드를 건너뛴다. 다른 로컬 변경이나 미게시 커밋이 있으면 보존하고 보류한다. 전체 대국·경험 DB·snapshot·optimizer·체크포인트·미채택 후보·임시 파일은 로컬에 유지한다. 강제 추가·강제 push·로컬 삭제·다른 자동화 변경은 하지 않는다. 완료·실패·필요한 조치만 알린다.
