## 9. 다음 작업 권고와 재개 절차

다음 조사는 **패배 대국에서 모델이 바꾼 수와 그로 인한 손해**를 확인하는 데 우선순위를 둔다. 학습 정답, 특징 표현, 엔진에 반영되는 평가값·추론 비용 중 어떤 요인이 성능 개선을 제한하는지 좁힌다. 현재 근본 원인은 아직 확정되지 않았다.

1. 서버·실행 PID와 최신 저장 파일을 다시 확인한다. 이 문서의 상태를 현재 상태로 가정하지 않는다.
2. 최신 완료 평가는 `arena-cycle-2.json` 및 `.summary.json`의 trial 69다. 같은 cycle의 `trainingEvidence`를 사용한다. 현재 가변 candidate 파일은 cycle 3 후보다.
3. 학습 오차와 실제 대국 성능을 분리해서 보고하고, 다른 후보의 평가 점수를 합산하지 않는다.
4. 평가 결과를 보고 같은 trial의 표본 수·후보·기준을 바꾸지 않는다. 실패한 평가를 새 예산처럼 초기화하지 않는다. 개선 가설은 개발 자료에서 점검하고 이후 새 후보의 독립 평가 계획을 결과 전에 고정한다.
5. 같은 실행을 재개할 때는 **저장 예산도 올려야 한다**. 수정된 대시보드에서 **`run-20261009164620115-30c039`**을 선택하고 **「재개 저장 예산 (GiB)」에 12**를 넣은 뒤 **「저장한 지점에서 재개」**한다. 같은 cycle 3 후보·CPU 13개·검증 설정을 이어간다. CLI 경로도 별도 fixture에서 확인했다:

   ```powershell
   node tools/learning/run.cjs cycle --run=outputs/learning/runs/run-20261009164620115-30c039 --resume --max-disk-gb=12
   ```

   12 GiB는 현재 준비 검사를 통과할 여유가 있으나 이후 누적을 무기한 보장하지 않는다. 실제 예산 검사는 계속 적용된다. 대시보드는 disk-budget로 중단된 실행에서만 저장 한도 증가를 허용하며, 일반 재개는 저장 설정을 유지한다.
6. 서버 시작은 `outputs/start-learning.cmd`, 화면 주소는 `http://127.0.0.1:8766`이다. 브라우저만 닫아도 서버와 학습이 종료되는 것은 아니다.
7. 중단할 때는 **「중단 요청」 → 저장 후 중단 확인 → 서버 종료** 순서를 사용한다.

이번 후속 작업은 읽기 전용 감사, 모델 경로 조사 및 저장 예산 재개 UI/API 보완을 수행했다. 기준 완화·다음 장시간 평가 예약·프로덕션 재시작은 수행하지 않았다. 예약 없이 계산한 trial 70의 powered 계획은 상대별 **1,206가족**, 총 **4,824대국**, 필요한 점수 **56.9070% 초과**다. 실제 번호·계획은 재개 시 공유 원장에서 다시 확인한다.

근본 원인에 관해 확인한 범위: trial 69의 학습 정답은 대부분 생성 대국의 terminal outcome이고, 80ms 생성 정책의 결과 회귀가 1,000ms 검증에서 더 좋은 수 선택을 직접 학습하는 것은 아니다. 모델은 기존 정적 평가에 가산되며 기존 후보 제한·전술 증명 경로를 유지한다. 명백한 관점 반전·정규화·추론 일치 버그는 찾지 못했다. **학습 목표·후보 순위·추론 비용 중 무엇이 기력 개선을 제한하는지는 아직 확정되지 않았다.** 개발용 고정 국면에서 no-model / scale=0 / 실제 후보의 선택과 fixed-work 비용을 분리하는 진단을 다음 우선순위로 둔다.

이번 변경의 검증: 새 저장 예산 API 검사, 새 실제 브라우저 재개 흐름, 기존 dashboard·recovery API, 기존 대시보드 UI·monitor UI, 후보 선택 표시 검사가 통과했다. 새 검사는 허용된 한도 증가만 전달, 잘못된 요청·진행 중 실행 차단, 일반 재개의 설정 유지, 입력값의 폴링 보존과 휴대전화 폭을 확인한다. 모두 격리 fixture/가상 실행기를 사용했다. 독립 코드·문서 검토에서 추가 결함은 발견하지 못했다. 마지막 원본 확인에서도 cycle 3 stopped/8 GiB/trial 미예약이 유지됐고, 엔진·학습 실행기·native runtime identity는 저장된 실험과 일치했다. `git diff --check`도 통과했다.

## 11. 자동 동기화 상태

자동화 ID는 `github`, 이 채팅의 heartbeat 방식이며 마지막으로 적용한 설정은 활성·하루 1회다. 저장된 프롬프트는 다음과 같다.

> 이 프로젝트의 로컬 변경을 AGENTS.md와 .gitignore에 따라 검증·커밋·push하고 원격 일치를 확인한다. 충돌·진행 중 작업은 보존하고 다음 실행으로 미룬다. 강제 push나 로컬 삭제는 금지한다. 변경이 없으면 조용히 유지하고 완료·실패·필요한 조치만 알린다.

문서 작성 중 자동화 설정은 다시 변경하지 않았다. 자동화 상태나 스케줄 변경을 요청받으면 도구로 현재 설정을 확인한다. 실험 결과 모니터링 자동화는 별도로 만들지 않았다.
