# 3·3 금수 유도 사전 검사 — v5.18.2

상대가 미래의 방어점을 3·3 금수로 만드는 준비 수를 찾고, 그 함정을 허용하는 후보를 증거가 있을 때 제외한다. 선후공·색에 고정된 수동적 성향을 추가하지 않았다. 즉시 승리·강제승 우선, 공격 지속·반격 후보, 정확한 5목 우선·양측 3·3 규칙과 신경망 입력은 유지한다. 학습은 재개하지 않았다.

## 원인과 변경

금수 방어점으로 끝나는 연속 4 탐색은 이미 있었다. 누락은 그 전에 두는 준비 수의 발견 경로다. 기존 Reader의 일반 준비 공격 검사는 평가 상위 12개와 현재 열린 3을 중심으로 검사했다. 더 넓은 반격 증명도 있었지만 국면·호출·시간 조건에 따라 모든 최종 후보에 적용되지 않았다.

새 `Reader.forbiddenTrap`은 현재 3·3 또는 3 한 축이 있는 방어점으로 연결되는 5칸 창에서 상대 준비 수를 수집한다. 이는 최대 16개의 공격 후보를 고르는 기준일 뿐, 위험·패배 증거가 아니다. 준비 수를 실제로 둔 뒤 **모든 합법 방어 응수**를 기존 VCF·반격 증명으로 확인한다. 즉시 역승, 반격 4, 공격 지속 수를 생략하지 않는다. 유일한 즉시 5목 방어만 강제되는 경우에는 그 합법 방어와 비차단 수의 즉시 패배를 구분한다.

증거에는 실제 금수 말단의 좌표·보드 키·3축과 그 지점에 도달하는 합법 수순을 남긴다. 전체 응수 검증이 끝난 경우에만 후보를 반증한다. 시간 초과는 `complete:false, proof:null`이며, 일부 응수만 확인한 결과를 패배·안전의 증거로 사용하지 않는다. 세부 증명 옵션에서는 전체 분기 트리를 내보내 별도 규칙 구현으로 재검증할 수 있다.

통합 엔진의 초기 후보 검사, 자동의 예약된 최종 검사, 심층·병렬의 상위 후보 검사에 연결했다. 자동의 최종 검사 예약은 기존 총 예산 안에서 최대 400ms이고, 심층·병렬도 기존 예약 시간을 나누어 사용한다. 빠르게 1초·자동 15초·심층 25초 상한은 유지한다. 미검사 대안은 검사된 다른 후보의 완료 상태를 물려받지 않는다. 완료된 반증은 진행 메시지·시간 종료·최종 추천에 보존한다. 캐시 이름은 `node-v3`, 엔진 표시는 `unified-initiative-2-forbidden-1`로 구분한다.

## 재현과 검증 범위

아래 좌표는 테스트 파일의 **A1=배열 0** 표기다. 앱의 위쪽을 15로 표시하는 화면 좌표와 혼동하지 않는다.

- 생성 국면의 내 돌은 `C8 D7 D9 C7 E9 H7 G7 I9`, 상대 돌은 `E8 F8 K2 K3 B2 B3 M12 M13 B12 B13 H13 H14`다. 내 후보 `H9` 뒤 `H8`은 금수가 되고, 상대의 준비 `G8`은 기존 일반 평가 순위 13번(0부터 시작)으로 상위 12개 밖이다. 직접 VCF도 없어 기존 일반 준비 검사는 놓친다. 보존한 수정 전 실행기에서도 같은 누락을 확인했다.
- 새 검사는 `G8` 뒤 **198개 합법 응수 전체**를 증명한다. 흑백 교환·8개 대칭의 16개 사례에서 총 **3,168개 응수**를 별도 규칙·증명 DAG 검사로 확인했다. 금수 말단의 보드와 수순도 대조한다.
- 실제 최종 후보 검사에서 `H9`는 반증하고 공격 후보 `H8`은 유지한다. `H8` 뒤 내 차례라고 가정한 국면에는 공격 수순이 있지만, 이 자체를 원래 국면에서 모든 상대 응수에 이기는 증명으로 부르지는 않는다.
- 반격 4로 탈출하는 변형, 즉시 역승, 정확한 5목 우선으로 합법이 되는 방어점에서는 잘못된 금수 함정 증명을 만들지 않는다. 시간 초과·0ms·재사용 시계·보드 복원도 검사한다.
- 접근 가능한 95수 기보의 `H5 → I4` 금수 변화와 기존 22수 기보의 `C8 → E7`, 이후 `E10` 금수 방어 수순을 별도로 재생·검증한다. 이 늦은 기보 국면 중 일부는 구 엔진도 인식하므로 모두 신규 개선 사례라고 주장하지 않는다.

`test/forbidden-trap.cjs`는 위 증명·반례와 실제 Search/최종 후보 검사 경로를 검사한다. `test/forbidden-trap-ui.cjs`는 공개 기본 외형의 작은 생성 fixture에서 네이티브 Edge Worker를 사용한다. 의도적으로 검사 대상으로 지정한 함정 후보에 대한 전체 증명과 실제 자동·심층 실행을 구분한다. 실제 일반 분석에서는 다른 합법 수가 추천됐고, 함정 후보가 최종 후보에 없을 수 있었다. 따라서 **전체 엔진의 선택 변화나 보편적 기력 향상**으로 확대하지 않는다.

기존 공격 지속·방어 후 역공·상대 실수 포착·강제승 조기 확정 검사, 합법성·시간 상한·캐시·Worker 정리·공개/비공개 외형 분리도 재검증한다. 최초 전체 검사 시 추가 API의 위치가 테스트용 내부 탐색 노출 표식을 가렸고, 기존 표식을 유지하도록 정리했다. 전술 판정의 실패로 숨기거나 기존 검사를 삭제하지 않았다.

최종 검증은 `npm test` 종료 코드 0(35개 통합 시나리오 실패 0), 기존 Edge 모드·강제승 검사와 새 `forbidden-trap-ui.cjs` 통과다. 검토 중 보완한 미검사 후보의 미완료 표시·최종 탐색 노드 합산에 대해서도 영향받는 모드·병렬·캐시 검사를 다시 통과했다. 새 Worker 검사에서는 흑백 각각 198개 응수 증명을 별도로 검증했고, 일반 자동·심층 실행은 시간 상한·합법 PV·보드 복원·활성 Worker 0개를 확인했다.

## 보존과 한계

최근 사용자가 관찰한 실제 대국 기보는 아직 확보하지 못했다. 위 내용은 접근 가능한 기보와 생성 국면의 증거이며 해당 대국을 그대로 재현했다는 뜻이 아니다.

이 검사는 제한된 준비 후보·깊이·시간을 사용한다. 더 긴 준비 수순이나 후보 밖 함정은 여전히 놓칠 수 있다. 미발견을 안전으로 표시하지 않으며, 확정된 패배 후보만 제외한다. 학습된 가중치를 새로 채택하거나 장기 대국 평가를 실행하지 않았다.

기존 중단 실험·기보·학습 결과·미완료 평가·체크포인트와 활성 모델, `.local/appearance.json` 및 이미지를 그대로 보존한다. 중단된 trial 95는 934/6,800에서 유지한다. 이번 엔진 변경 결과를 그 과거 평가의 식별자로 덮어쓰지 않는다. 향후 학습·채택 재개 시에는 변경된 엔진에 맞는 별도 실험·평가 경계를 적용해야 한다.

실험 3개의 상태·진행·설정·후보·보고·체크포인트·평가 파일과 활성 모델·개인 외형 등 보호 파일 21개의 SHA가 작업 전과 같은 것을 확인했다. 검사 중의 생성 fixture는 기존 실험을 재시작하지 않는다. 최종 소스 식별자는 `b9f59b277fc1d75c566e0d00f0c565350753f36f6daa5ff5471cd8818da53689`이며, 수정 전 실행기도 로컬에 보존했다.

공개 배포물은 `dist/index.html`이다. 개인 외형과 저장 키를 사용하는 로컬 `outputs/omok.html`은 공개하지 않는다. 상세 검사 로그·수정 전 실행기·증명은 ignored `work/forbidden-trap-20261023/`에 둔다.
