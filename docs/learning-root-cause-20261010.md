# cycle 4~6 기력 정체 조사와 개선 실험안

2026-10-10, Asia/Seoul. 사용자가 제기한 표본 부족, 신경망 깊이, 비교군, 실행 흐름을 각각 조사했다. 실행 감사 기준 시각은 **21:27 KST**이며 진행 중인 대국의 부분 점수는 분석·후보 선택에 사용하지 않았다.

## 판단

**현재 미채택을 단순한 표본 부족이나 얕은 신경망 하나의 문제로 설명할 수 없다.** 확인된 결함은 cycle 이력을 오해하게 만드는 화면 표시와, 앞서 개선한 Reader가 현재 실행에 적용되지 않은 사실이다. 학습 측면에서는 기존 정책의 대국 결과를 대부분 반복 학습하며 더 깊은 탐색의 교정 신호가 거의 없는 구조가 우선 조사 대상이다. 이 구조가 기력 정체의 주원인인지는 통제 실험으로 확인해야 한다.

모델은 CUDA에서 실제로 학습하고 있으며 무의미한 0 예측보다 검증 오차가 낮다. 하지만 최근 추가 오차 개선은 작고, 완료된 trial 71의 53~54% 점수로는 현재의 보수적인 채택 기준을 넘는 개선을 입증하지 못했다. 개선이 전혀 없다는 증명과 채택 증거가 부족하다는 판단은 다르다.

## 표본은 무엇이 부족한가

학습 표본과 최종 기력 검증 표본은 서로 다른 문제다. 더 많은 대국 검증은 작은 개선을 검출할 수 있게 하지만 모델을 더 강하게 학습시키지는 않는다. 누적 행 수가 증가해도 매번 학습하는 자료의 다양성이 같은 속도로 증가하지 않는다.

| cycle 6 학습 자료 | 값 |
| --- | ---: |
| snapshot 생성 당시 누적 source | 1,444,485행 |
| 선정 snapshot / 실제 train | 100,000 / 83,245행 |
| validation / 격리 test | 8,379 / 8,376행 |
| train / validation 가족 | 33,260 / 4,978개 |
| train terminal / teacher | 83,212 / 33행 |
| validation teacher | 0행 |
| teacher 유효 학습 가중치 비중 | 0.000010555% |
| cycle 5와 공유하는 train 가족 | 32,816 / 33,260 = 98.665% |
| cycle 5 이후 신규 train 가족 | 444개 |

98.665%는 **가족의 공유율**이며 행이나 보드가 그대로 같다는 비율이 아니다. cycle 3과 비교한 현재 train 공유 가족은 95.935%다. 현재 recent/history 절반씩 선택에서 recent는 이번 cycle의 새 12,725행만이 아니라 최신 약 300,504행의 pool이다. ‘누적 144만 행’, ‘10만 행 snapshot’, ‘8.3만 행 train’, ‘신규 444 가족’을 같은 분모로 비교하면 진행을 과대평가한다.

현재 family 가중치를 적용한 validation의 0 예측 MSE는 **0.941040578**, 후보는 **0.709426776**다. 후보 오차가 24.61% 낮으므로 학습 전체가 무효라는 해석은 맞지 않는다. 반면 같은 snapshot의 초기값 **0.709709635 → 0.709426776**은 절대 0.000282859, 상대 약 **0.03985%** 개선이다. MSE 0.709를 정확도 70.9%로 읽으면 안 된다. 서로 다른 cycle의 validation 모집단도 바뀌므로 cycle 간 MSE 숫자만으로 기력 추세를 판정하지 않는다.

cycle 6 학습은 실제 학습 45.56초, 전체 호출 75.60초에 early stop했다. 이번 종료를 120초 한도 부족으로 설명할 근거는 없다. raw validation 무승부 비율은 14.81%, family 가중치 적용 후 5.896%다. 반복 draw 가족의 행 수를 독립 관측 수와 혼동하지 않는다.

## 학습 목표와 생성 정책

현재 self-play는 **80ms 탐색·exploration 0.2**로 완료된 대국의 승패를 sampled position의 목표값 ±1/0으로 사용한다. 최종 arena는 **1,000ms**다. 실제 결과 label의 재생 검사는 통과했지만, 짧은 탐색에서 나온 한 대국의 결과가 해당 국면의 최선 수나 긴 탐색의 가치를 직접 알려 주지는 않는다. 12.5배의 시간 차이가 학습·평가 분포 차이를 만들 수 있다. terminal 학습 자체가 잘못된 방법이라는 뜻은 아니다.

현재 champion이 없어 self-play는 `model:null`로 생성한다. 미채택 후보의 가중치는 다음 학습 초기값으로 이어지지만 생성 정책에는 들어가지 않는다. 따라서 cycle이 늘어나도 새 후보의 더 나은 판단을 사용해 경험을 수집하는 순환이 현재 작동하는 것은 아니다. 검증되지 않은 후보를 champion으로 선언하는 해결책도 적절하지 않다.

600ms teacher 분석은 imported records에만 적용되고 fresh self-play에는 붙지 않는다. train teacher 33행 중 30행의 목표 절댓값은 0.01 미만이다. `tanh(score/200000)` 변환, confidence와 family 가중치를 적용한 teacher 기여는 약 10⁻⁷의 비율이다. 현재 자료에서 ‘더 깊은 탐색을 배우는 통로’가 실질적으로 매우 약하다는 것은 확인했다. 다만 teacher 수치의 스케일이 올바른지 확인하지 않고 가중치만 증폭하면 오히려 잘못된 감독을 강화할 수 있다.

AlphaZero의 원 논문은 보드에서 수의 확률과 국면 가치를 함께 예측하고, 탐색 방문 분포와 대국 결과로 학습하며 갱신된 네트워크로 다음 self-play를 생성한다. 우리 구현은 이 전체 학습 순환과 다르다. 여기서 가져올 점은 ‘더 깊은 층’이라는 이름보다 **탐색이 만든 학습 신호와 다음 경험 수집에 전달되는 경로**다. 이 비교로 같은 자원에서 AlphaZero 성능을 재현할 수 있다고 주장하지 않는다. [원 논문](https://arxiv.org/pdf/1712.01815)

## 얕은 신경망이 원인인가

현재 모델은 **32 → 16 ReLU → 1 tanh**, 학습 파라미터 **545개**인 작은 value MLP다. GPU로 학습하므로 신경망 학습은 맞지만 깊은 공간 신경망이나 policy/value 모델은 아니다. 32개 입력은 양쪽 색의 5칸 창 패턴 개수, 돌 수, 중앙 가중치, 선수 문맥 등의 집계다. 특정 좌표, 위협들이 같은 빈 칸에서 교차하는 관계, 공간 배치를 직접 전달하지 않는다.

작은 모델의 용량과 입력의 정보 손실은 서로 다른 가설이다. 집계에서 사라진 위치 관계는 같은 32개 특징에 층이나 hidden 크기만 늘려도 복구되지 않는다. 반대로 입력을 바꾸는 복잡한 신경망은 CPU 추론 비용 때문에 같은 1초 안에 탐색할 노드 수를 줄일 수 있다. 따라서 더 깊은 모델을 바로 넣는 것보다 **학습 신호 → 현재 특징의 용량 → 공간 표현** 순으로 한 가지씩 비교하는 편이 원인을 가릴 수 있다.

이를 반례로 점검하기 위해 현재 validation binary를 새로 집계했다. 8,379행의 exact Float32 32-feature 그룹은 8,378개이고, 유일한 중복 2행의 label은 같았다. 각 고유 특징에 임의 값을 붙일 수 있는 함수의 경험적 oracle MSE 하한은 0이며, 현재 관점 반전의 부호 제약을 추가해도 0이다. 따라서 **현재 MSE 0.709를 동일 특징에 충돌하는 label 때문에 불가피한 오차라고 설명할 수 없다.** 대부분 고유한 유한 표본을 외울 수 있다는 계산이므로 작은 MLP의 용량·일반화·근접 특징의 정보 손실이 충분하다는 증거로도 쓰지 않는다. 과거 자료의 feature 충돌 하한을 현재 자료의 원인으로 재사용하지 않았다.

오목 엔진 Rapfi의 공식 구현도 alpha-beta 탐색과 효율적인 NNUE 평가를 결합한다. 깊은 범용 CNN만이 기력 개선 경로는 아니다. Rapfi와의 직접 성능 비교나 규칙 호환성은 이번에 검증하지 않았다. [공식 저장소](https://github.com/dhbloo/rapfi/blob/master/Readme.md)

## 비교군과 채택 표본

trial 71에는 기존 baseline과 **같은 엔진에서 모델만 끈 current-no-model**이 모두 있었다. 두 상대 모두 규칙·모델 일치·완료 조건을 통과했다. 잘못된 비교군 때문에 탈락했다는 증거는 찾지 못했다. current-no-model 비교는 모델의 추가 효과를, baseline 비교는 기존 기준 엔진에 대한 전체 효과를 묻는다. 이 결과는 기록된 규칙·opening·1초 시간에서의 상대 점수이며 보편적인 Elo를 뜻하지 않는다.

채택 gate는 가족별 흑백 교환 점수의 Hoeffding 하한이 상대마다 50%를 엄격히 초과해야 한다. 반복 후보 선택의 오류 예산은 공유 trial 원장의 `alpha_t = 0.05 / (t(t+1))`로 지출된다. 현재 약 1,200 가족의 자동 계획은 각 상대에 대한 **진짜 평균 점수가 최소 60%**라는 가정에서 두 상대 전체의 보수적인 통계적 통과 확률 하한 80%를 계획한 것이다. 모든 가정과 다른 gate가 충족된다는 보장은 별개다.

21:30 KST 읽기 전용 원장의 다음 trial은 73이었다. 예약하지 않고 현재 공식을 대입한 다음 수치는 작은 효과를 최종 채택으로 입증하는 비용을 보여 준다.

| 가정한 실제 평균 점수 | 그 점수가 관측됐을 때 하한 통과에 필요한 가족/상대 | 보수적 조건부 80% power 계획 가족/상대 | power 계획 총 대국(두 상대) |
| --- | ---: | ---: | ---: |
| 60% | 580 | 1,212 | 4,848 |
| 55% | 2,319 | 4,845 | 19,380 |
| 53% | 6,440 | 13,459 | 53,836 |

첫 숫자 열은 관측 점수에 대한 대수적 경계이며 power 계산이 아니다. 실제 효과 크기는 알려져 있지 않고 위 계획도 실제 power의 추정치가 아니다. 새로운 가족 ID 자체가 통계적 독립성을 증명하지 않으며, 고정 후보 이후의 새 가족 점수가 독립인 [0,1] 관측이고 각 상대의 평균이 가정한 점수 이상이라는 조건이 필요하다. 55%·53% power 계획은 planner preview의 기본 상한(4,096 가족/상대·16,384대국)과 현재 production arena의 저장 상한(2,048 가족/상대·두 상대 8,192대국)을 모두 넘는다. **완료 결과를 보고 기준을 낮추거나, 원장을 초기화하거나, 진행 중 trial의 대국 수를 늘리는 방식으로 해결하지 않는다.** 개발 검증으로 충분히 큰 개선의 근거를 만들고 잠근 후보의 최종 독립 검증 비용을 사전에 결정해야 한다.

## 실행할 개선 순서와 판정 기준

현재 arena를 보존하고 다음 개발 실험들을 순차적으로 분리한다. 아래는 계획이며 실행·기력 향상이 완료됐다는 기록이 아니다. 기존 격리 test와 진행 중 arena의 결과를 개발 후보 선택에 사용하지 않는다. 생산 경험 DB·노출 계보·공유 원장은 유지한다.

1. **새 Reader가 실제로 실행되는지 먼저 닫는다.** 현재 continuous runner는 arena 이후 다음 cycle로 진행하므로 arena 완료가 runner 종료는 아니다. 전환 시에는 협조적 stop으로 저장하고 runner lock 해제를 확인한 뒤, 남은 고정 trial을 standalone `validate --resume`의 보관 코드로 마친다. 이 standalone 종료 후 완료 대국·후보/자료/실행 identity와 새 stop 요청 없음을 확인하고 현재 소스의 별도 `--from-run` 실행으로 이어받는다. 기존 trial 71 전환 helper는 cycle과 후보를 고정했으므로 trial 72에 재사용할 수 없다. 구 코드의 채택 증거를 새 엔진의 증거로 옮기지 않는다. 동일 개발 국면의 고정 탐색량 일치와 1초 처리량을 먼저 확인한다. 이번 조사에서는 runner를 중단하거나 이 전환을 실행하지 않았다.
2. **fresh 자료에 유효한 teacher 감독을 만드는 개발 실험을 먼저 한다.** outcome을 열기 전에 fresh train 가족 256개와 별도 development 가족 64개를 hash 순서로 고정하고 가족당 하나의 합법 비종료 국면을 선택한다. development는 warm-start 전체 노출 계보와 기존 arena 가족에 없던 가족으로 확보하고, train/development 국면·가족을 이후 최종 arena 제외 등록부에 모두 기록한다. 작은 pilot은 이 같은 256 train 국면만 사용하며 terminal-only와 teacher 혼합을 같은 모델 초기값·16 hidden·shuffle seed 3개로 비교한다. 양쪽은 같은 행·가족 가중치·batch 64·batch 순서·epoch 20(80 update)·최종 epoch 모델을 사용하고 early stop은 사용하지 않는다. teacher 혼합은 행을 추가하지 않고 고정된 목표 혼합(terminal 75%·교정 teacher 25%)만 바꾼다. teacher는 같은 고정 규칙의 current-no-model 엔진에서 최대 2초 탐색으로 만들고 탐색 완료 깊이·점수·PV·시간을 보존한다. 미완료·규칙 위반·증명 불일치는 실패로 기록하며 0 label로 대체하지 않는다. teacher가 없는 동일 국면에 임의 깊이 점수를 붙이지 않는다.
3. **teacher의 의미를 먼저 확인한다.** 기존 score 스케일을 임의로 키우지 않는다. train 국면의 증명된 승리·필수 방어와 점수 분포를 확인하고 scalar 점수의 교정 규칙을 train에서 정한 뒤 잠근다. development 64가족은 교정·목표 선택에 사용하지 않고 고정 평가로 남긴다. parent scalar teacher와 child 수 순위는 서로 다른 과제이므로 이번 pilot에서 pairwise 목표까지 함께 바꾸지 않는다. scalar가 유효한 감독으로 확인되지 않으면 pilot을 멈추고 별도 pairwise 설계를 만든다. 혼합 목표의 family별 유효 비중과 종류별 오차를 기록해 teacher가 다시 사실상 0이 되는 것을 막는다. validation에 teacher가 없다는 상태에서는 teacher 일반화를 검증했다고 부르지 않는다.
4. **MSE가 수 선택으로 전달되는지 본다.** 같은 고정 development 국면에서 no-model과 후보의 점수·root 후보 포함 여부·선택 수·완료 깊이·노드·추론 시간을 대조한다. 고정 탐색량 검사와 80/1,000ms 검사를 구분한다. 알려진 정답이 있는 경우만 정답률을 계산한다. 나머지는 수 선택 일치율과 teacher 순위의 관계로 기록한다. 규칙 회귀가 있거나 MSE만 낮아지고 수 선택·탐색이 나빠지면 그 후보를 최종 arena에 보내지 않는다.
5. **그 뒤 용량과 표본의 영향을 따로 시험한다.** 현재 특징 16 vs 64 hidden은 동일 자료·초기화 정책으로 용량을 비교하고, 공간/선 패턴 입력은 별도 feature version·parity·노출 계보를 가진 실험으로 비교한다. 데이터 양은 가족 단위의 중첩된 20k/40k/80k train 행 구성, 동일 holdout·seed 3개·teacher 비중으로 학습 곡선을 만든다. 행 수뿐 아니라 고유 가족과 신규 가족을 함께 보고하고, 시간 제한으로 덜 학습한 큰 자료를 수렴한 작은 자료와 같은 조건이라고 부르지 않는다.

첫 teacher pilot은 320국면·국면당 최대 2초의 **탐색 시간 배정**과 epoch 20·호출 120초·순차 CUDA 6회의 상한을 먼저 기록한다. 이는 실제 CPU 시간이나 종료 ETA가 아니다. 준비·검색·학습 전체 wall time은 30분에서 종료하고 미완료 arm은 미완료로 남긴다. 생산 runner의 협조적 저장·종료와 lock 해제를 확인한 뒤에만 pilot을 실행하며, arena 완료만 보고 연속 runner와 자원을 경쟁시키지 않는다. 자원 초과 시 표본·초기값을 슬쩍 변경해 계속하지 않는다. 이 작은 pilot은 유효한 신호를 만드는지 확인하는 단계로, 256 가족만으로 대규모 모델의 최종 우수성을 선언하지 않는다.

pilot의 사전 1차 지표는 development 64가족의 teacher MSE에 대한 두 arm의 가족별 paired 차이다. 세 seed 각각 혼합 arm의 평균 오차가 terminal-only보다 1% 이상 낮고, 같은 development terminal MSE 악화가 1% 이내이며, 기존 규칙·parity 검사에 실패가 없어야 다음 규모 실험으로 진행한다. 이 1%는 개발용 최소 실용 효과이며 유의성·기력·채택 기준이 아니다. 양쪽 오차가 거의 0이면 상대율 판정이 의미 없어 실패/추가 설계로 기록한다. 64가족·80 update의 작은 pilot 실패로 teacher 전체의 무용성을 선언하지 않는다. 후속 수 선택과 시간 예산 검사를 통과한 개발 후보 하나를 선택한 뒤 별도 새 가족과 그때의 shared trial로 기존 채택 gate를 적용한다. 수치 선택 기준·자료 hash·seed·계산 자원은 실행 전에 잠그고 여러 개발 seed의 점수나 서로 다른 후보의 arena를 합쳐 채택 근거로 만들지 않는다.

## AI-Lecture 적용과 근거의 범위

GitHub 연결로 `jiho6367-design/AI-Lecture`의 README, **1~9강 각 README 요약**, `만능_프롬프트_가이드.md`를 읽었다. 전체 강의 받아쓰기나 영상 완독을 주장하지 않는다. 비공개 강의 원문은 이 공개 프로젝트 문서에 복제하지 않는다.

적용은 실행 가능한 조사로 구체화했다. 사용자의 질문을 표본·표현·학습 목표·대조군·실행 귀속으로 나누고, 화면 설명보다 원본 저장 기록을 우선했다. runtime/arena와 data/objective를 독립 감사한 뒤 반례를 대조했다. ‘GPU가 안 배운다’, ‘cycle 5 유실’, ‘시간 부족’, ‘딥러닝만 넣으면 해결’, ‘채택 안 됐으니 개선 0’이라는 설명을 실제 기록으로 점검했다. 확정 사실과 가설을 구분하고 다음 실험을 한 가지 변화씩 비교하도록 제한했다. AI의 제안이나 MSE를 채택 증거로 바꾸지 않았다.

원자료는 ignored 로컬 폴더에 보존한다. 현재 run은 `run-20261009164620115-30c039`이며 cycle별 snapshot manifest·prepared binary·checkpoint·adoption 결정과 완료 arena summary를 대조했다. 실행 감사는 `work/strength-investigation-20261010/audit-cycle4-6-1791635228838.json`에 있다. 최종 test는 학습 metadata의 행 수만 확인했으며 test features·labels·성능은 이번 개발 판단에서 열지 않았다.

현재 특징 충돌의 새 감사는 `work/diagnostics/cycle6-feature-oracle-20261010T123142175203Z.json`에 있다. validation binary hash를 manifest와 대조했고 한 CPU의 표준 라이브러리 집계는 0.066초였다. 모델 훈련이나 생산 자료 수정은 하지 않았다.
