확인한 규칙과 기존 기반
15×15, 흑/백 양쪽 33 금수, 정확한 5목 우선 승리, 44 허용, 6목 이상은 승리 아님. 백 선공도 가능하고 중앙 강제 시작은 없습니다. 선택한 40초 초과는 돌 없이 차례만 바뀌는 PASS입니다. 실제 정확한 5목 또는 만판만 종료 라벨이며 연속 PASS·합법수 없음·실험 시간/수 제한은 임의의 무승부로 만들지 않습니다.
기존 Reader/Forest 수읽기, 전술/반증 검사, 준비 패턴, 59,049개 정적 패턴표, v5.15 턴 간 메모리를 사용합니다. 기존 앱·Reader·보고서에서 31개 기보/국면을 규칙대로 복원했고 앱 35수 교훈 1개도 기존 휴리스틱으로 보존했습니다. 외부 렌주 규칙이나 새 엔진으로 교체하지 않았습니다.

학습 구조
CPU: 기보 복원, 이전 국면 재분석, 합법 대안/변형 대국, 실제 착수 수읽기, 승패 대결과 검증.
GPU: 기존 패턴과 국면의 32개 특징을 받는 32→16→1 가치 신경망 학습.
학습한 가중치는 JSON으로 내보내 Reader/Forest CPU 평가에 ±600 이내 보정을 더합니다. 즉시 승리·금수·필수 방어·확인된 반증이 우선입니다. GPU가 대국 때 반드시 켜져 있어야 하는 구조는 아닙니다.
기보·누적 자료·후보 가중치·optimizer/RNG/커서 체크포인트를 저장합니다. 미채택 후보도 다음 학습의 출발점으로 이어받지만 실제 기본 대국은 채택 모델만 사용합니다. 학습은 반복 코드 수정이 아니라 평가 가중치 갱신입니다.
원본/prefix/대칭/색 교환의 자료 계열을 묶고 정확히 같은 국면의 split 교차 중복을 제외합니다. 패배 경기 전체 착수를 나쁜 행동으로 처리하지 않습니다. 실제 결과와 제한 탐색의 약한 teacher 추정을 구분합니다. 최종 test 기보는 자동 arena에서 사용하지 않습니다.

첫 실행의 8판/693표본/학습값을 새 실험으로 해시와 이전 기록을 남겨 이어받았습니다. 총 완료 변형 대국 15판(처음 8판+추가 7판), 분석 89국면, 원본 표본 780개, 고정 snapshot의 고유 국면 672개입니다. 진행 중 변형 1판도 보존했습니다.

실제 첫 후보의 CPU 평가 8국면과 24회 수읽기 모두 합법/보드 복구/모델 버전 정상. 누적 특징+신경망 평균 2.89 µs, 특징을 새로 계산하면 191.87 µs, 해당 Node 측정 최대 RAM 299.01 MiB. Forest의 특징 재계산 비용은 있어 모든 탐색이 더 빨라졌다고 주장하지 않습니다.
합성 warmed 학습 batch 256에서는 GPU가 CPU보다 느렸고 batch 16,384에서는 약 1.97배 처리량이었습니다. 이는 대국 생성이나 전체 엔진 속도가 아닙니다. 현재 작은 자료에서는 CPU 자료 생성/대결 쪽이 더 오래 걸립니다.

독립 대국 결과와 자동 판단
v5.15.0 고정 기준에 기존 교훈을 양쪽 동일 적용, 착수 예산 200 ms 동일, 새 예약 국면 32계열에서 선후공을 바꾼 64판을 모두 실제 종료까지 대국했습니다. 후보 30승 34패 0무, 미완료 0판, 점수율 46.88%입니다. 보수적 신뢰하한 22.87%가 50% 초과 기준을 통과하지 못했습니다.
채택 결과: kept-current, 기존 기본 평가 유지. 32쌍 중 실제 착수 수순이 동일한 쌍은 2개였습니다. 이번 자료/특징/학습 보정은 이 조건에서 기준을 넘어서는 대국 개선을 만들지 못했습니다. 같은 실험을 횟수만 늘려 자동 개선으로 보고하지 않습니다.
이 결과로 전체 기력 악화가 통계적으로 확정된 것도 아닙니다. 더 긴 실제 사용 착수 시간, 여러 상대, 더 다양한 원본 자료와 최종 test 기보의 확인은 남아 있습니다. 상대 모든 합법 대응에 대한 필승 증명과 bounded 평가/실제 표본 승률도 구분합니다.
실제 중단 후 같은 후보와 대국을 재개해 먼저 완료한 7판과 진행 중 11수를 그대로 보존했고 64판까지 이어갔습니다. 원본 실험 파일도 해시가 그대로입니다. 41개 기존/신규 검사 프로그램, 보강된 pipeline 23항목, Python 11항목, 실제 HTML Worker 화면 13흐름 및 실제 대시보드 표시를 확인했습니다. 보강 이후 영향 있는 검사를 다시 실행했습니다. 긍정 배포/중간 실패 롤백은 격리된 테스트 경로에서 검사했으며 미검증 후보를 사용자 실행본에 넣지 않았습니다.

사용 방법
outputs/start-learning.cmd를 더블클릭하고 http://127.0.0.1:8766을 엽니다. 서버 창을 열어 둡니다. 앱의 JSON 내보내기 자료를 가져오면 기보와 기존 lessons가 함께 보존됩니다. 브라우저 localStorage에만 있는 자료는 JSON 내보내기가 필요합니다.
짧은 점검은 4쌍 연결 확인 전용이며 채택 기준 32쌍을 충족할 수 없습니다. 개선 학습에는 새 실행 이름으로 표준 설정을 선택합니다. 화면에서 실행/중단/재개와 결과·후보·채택 모델 다운로드를 사용합니다.
저장소에서 명령 실행:
  npm run learning
  node tools/learning/run.cjs cycle --run=outputs/learning/my-run --input=C:/path/records.json --games=128 --pairs=32 --minutes=60
  node tools/learning/run.cjs stop --run=outputs/learning/my-run
  node tools/learning/run.cjs cycle --run=outputs/learning/my-run --resume --minutes=60
  node tools/learning/run.cjs status --run=outputs/learning/my-run
이미 평가를 시작한 run의 착수 시간/대결 쌍은 바꾸지 않습니다. 소스/규칙/특징이 바뀌면 새 run이 필요하며 원본은 유지합니다. 이번에 실시한 호환 자료 이관은 migration.json에 기록했습니다.
채택 조건을 통과하면 src/active-model.json과 기존 HTML 다섯 파일에 동일한 모델이 들어갑니다. 모델 교체 시 이전 평가의 수읽기 메모리를 지우고 다음 분석/상대 예상/내 응수/복기에 새 모델을 전달합니다. 기존 페이지에는 새 HTML을 다시 열거나 채택 모델 가져오기를 사용합니다. 실패 시 기존 모델/HTML을 복구하며 GitHub push를 자동 실행하지 않습니다.
