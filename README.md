# 숲속 오목 · GPU 혼합 수읽기 v5.13.1

`omok-reader`의 빠른 수읽기와 `forest-omok-lab`의 캐릭터·저장·복기를 합친 하나의 오프라인 프로그램입니다. 주 개발 저장소는 [forest-omok-lab](https://github.com/jiho6367-design/forest-omok-lab)입니다. 이전 `omok-reader` 저장소의 코드와 이력은 이 저장소의 [omok-reader 브랜치](https://github.com/jiho6367-design/forest-omok-lab/tree/omok-reader)에 보존합니다. 최신 개발과 실행본은 `main`입니다.

## 실행

저장소를 ZIP으로 다운로드하고 압축을 푼 뒤 **`outputs/omok-gpu.html`** 또는 **`outputs/omok.html`**을 Chrome 또는 Edge로 여세요. 기존 경로인 **`dist/index.html`**도 동일한 프로그램입니다. 서버, 설치, 인터넷 연결은 필요하지 않습니다. 이미지와 분석 Worker 코드가 HTML에 포함되어 있습니다.

1. **새 게임**에서 내 캐릭터와 선후공을 각각 선택합니다. 노란 버섯은 흑, 초록 슬라임은 백입니다. 흑 후공도 가능합니다.
2. 규칙은 **정확한 5목 우선(숲속 기존 규칙)**으로 고정됩니다. 일반적인 양측 3·3은 금지하지만, 정확한 5목과 3·3이 동시에 생기면 5목 승리를 우선합니다. 4·4는 허용하고 6목 이상은 승리가 아닙니다. 이전 규칙 선택지는 새 게임과 기보 가져오기에서 제거했습니다.
3. 상대의 착수까지 직접 입력합니다. **1순위 후보**가 현재 추천입니다. 후보를 여러 번 누를 필요 없이 해당 좌표를 실제 판에 두고 이 판에도 입력합니다.
4. 수읽기는 **자동**을 권장합니다. 즉시 승리·필수 방어를 먼저 보여주고, 일반 국면은 초반 최대 2.5초, 이후 최대 8초 내에서 비교합니다. 후보가 안정되면 조기 종료합니다. CPU 성능에 따라 실제 시간은 소폭 초과할 수 있습니다.
5. 더 긴 검사가 필요하면 **심층 15초 / 25초**를 선택합니다. 먼저 빠른 엔진이 후보를 표시하고, 남은 시간에 숲속 엔진이 더 깊은 연속 공격·준비 수·강제 방어 뒤 역공을 검사합니다.

## v5.13.0 — GPU 혼합 모드와 고정 규칙

- 연산 방식은 **GPU 혼합 / CPU 최적화 / 기존 CPU**입니다. GPU 혼합은 WebGPU로 59,049개 줄 패턴을 계산하고 CPU가 수읽기에 재사용합니다. GPU 결과는 CPU 기준값과 전수 비교한 뒤 사용합니다. GPU를 사용할 수 없으면 이유를 표시하고 CPU로 실행합니다.
- GPU 분석 모드는 **최적화(자동, 최대 15초) / 아주 빠르게(약 1초) / 심층 분석(최대 25초)**입니다. 내 수와 예상 응수에 적용하고 선택을 브라우저에 저장합니다. 상대 다음 수 예측은 1초이며, 시계가 켜져 있으면 남은 시간에 맞춰 줄어듭니다. 아래에서 직접 분석 시간을 지정하면 그 설정이 우선합니다.
- 줄별 돌 개수를 재사용해 수읽기 후보의 중복 점수 계산을 줄였습니다. `CPU/GPU 성능 비교`는 같은 깊이·노드·점수·수순을 계산하는 세 국면과 1초 예산의 전체 분석을 비교합니다. 최초 GPU 준비 시간은 별도로 표시합니다.
- **GPU 혼합이 기존 CPU보다 빨라진 결과와 GPU 자체의 속도 우위는 구분합니다.** 최적화 CPU도 비슷한 속도를 보이므로 주요 개선은 알고리즘과 패턴 재사용 효과입니다. 시간 예산 모드에서는 대기 시간 대신 탐색 노드와 완료 깊이가 늘어날 수 있습니다. 성능은 장치·브라우저·부하에 따라 달라집니다.
- 새 게임·저장 기보·텍스트 가져오기·학습 규칙 표시는 숲속 규칙으로 통일합니다. 저장된 착수 기록은 유지합니다. 추천은 제한 탐색이며 필승·무패를 보장하지 않습니다.

NVIDIA 노트북에서 브라우저가 Intel 내장 GPU를 선택할 수 있습니다. Windows **설정 → 시스템 → 디스플레이 → 그래픽**에서 실제 사용 브라우저를 고성능 GPU로 지정하고 브라우저를 완전히 다시 시작하세요. GPU 상태의 실제 장치 표시를 확인해야 합니다.

검증과 기존 회귀 실패의 수정 내용은 [GPU 검증 기록](reports/gpu/validation.md)에 정리했습니다. 아래 이전 버전 기록은 당시 동작과 검사 결과입니다.

## v5.13.1 — 반증 유지와 자동 검사 수정

Reader가 이미 반증한 후보를 심층 엔진이 다시 추천하던 경로를 차단했습니다. 자동 분석의 표시도 심층 결과를 채택하지 않은 경우에 유지합니다. 시간 제한 탐색의 회귀 검사는 특정 좌표를 안전한 정답으로 고정하지 않고 합법 수, 수순 유효성, 증거가 있는 반증 제외와 승패 표시를 검사합니다. 전체 강제패배가 증명된 경우에는 합법적인 저항 수와 패배 판정을 함께 유지합니다.

`omok-reader`는 이전 실행본을 보존하는 브랜치입니다. main에 보존 이력을 연결하되 최신 GPU 실행본에는 이전 소스를 덮어쓰지 않습니다.

v5.0은 확인된 강제승 시작점에서 벗어나는 착수를 다시 확인합니다. 분석 중인 임시 후보에는 팝업을 띄우지 않습니다. 30수 초록 기보에서는 C8을 강제승 시작점으로 확인해 B7·G12 두 승리점을 표시합니다.

v5.2는 심층 분석 결과도 실제 착수 뒤 상대의 강제승을 한 번 더 검사합니다. 19수 기보에서 사용자는 노란 버섯이며, 16수 H11이 허용하는 J7–K6/F11 강제승을 감지해 H11을 제외하고 G5 저항 후보를 유지합니다. 모든 후보의 패배가 확인된 국면은 후보가 있어도 `강제패배 확인`으로 표시합니다. 종료 화면에는 승리 캐릭터와 함께 `내 승리` 또는 `내 패배`를 표시합니다.

v5.3은 복사한 텍스트 기보 첫 줄에 내 돌과 선·후공을 기록합니다. 새 27수 노란 기보에서는 14수 E7이 초록 H7을 강제해 대각선 공격을 키운 분기점을 감지하고, 노랑 H7 선점으로 초록 E7 방어를 강제하는 재발 방지 패턴을 적용합니다.

v5.4는 저장된 복기 화면과 분리된 엔진 시작 단계에서 패턴 방어를 검사합니다. 31수 노란 패배 구조에서는 14수 H6 임시 후보를 노출하지 않고 D9을 즉시 최종 추천합니다. 같은 구조는 새 게임, 회전·반전된 판, 돌 색을 바꾼 판에도 적용됩니다.

v5.5는 26수 노란 패배 기보에서 15수 K9 이후 확인되는 초록 강제승을 더 일찍 차단합니다. 6수 G9 대신 H7을 선점해 기록된 H7–J8–G6 연결을 막으며, 새 게임과 회전·반전·색 교환 판에서 분석 시작 즉시 적용합니다.

v5.6은 상대 차례의 다음 수 예측을 선택한 분석 시간과 관계없이 1초로 고정합니다. 예상 상대 수가 나오면 내 응수는 화면에서 선택한 분석 시간(자동 모드는 자동 계산 시간)으로 미리 분석하고, 예상이 실제 착수와 일치하면 그 계산을 이어받습니다.

v5.7은 13수 초록 기보의 강제패를 8수 G11 선점으로 예방합니다. 12수 I5가 만드는 J4 승리 위협은 J4로 막힌 뒤 초록의 강제패를 숨기므로 25초 분석 결과를 필승으로 해석하지 않습니다. 새 게임 엔진은 동일 판과 회전·반전·색 교환된 판에서 G11 방어를 즉시 제시합니다.

v5.8은 한 칸짜리 5목 위협을 상대가 막은 직후의 강제 반격을 모든 새 게임 후보에서 검사합니다. 15수 기보의 12수 F7과 30수 기보의 23수 N8을 위험 후보로 낮추고, 심층 탐색이 패배로 배제한 후보를 빠른 탐색 결과에서 다시 추천하지 않습니다. 당시 제시한 12수 E10도 후속 수순에 따라 패배하므로 방어 해법으로 간주하지 않습니다.

v5.9은 E10 이후에도 패배한 33수 기보를 재분석합니다. 4수 G7·6수 I5는 백의 공격이 한 축에 치우치는 선택이지만 그 자체가 강제패배라는 증명은 없습니다. 독립된 공격축을 평가에 반영하고, 빠른 후보에 대해서도 한 칸짜리 승리점을 흑이 막은 직후의 반격을 먼저 검사합니다. 이 수순의 14수 F7→H7, 16수 D7→C7, 18수 J4→K3가 같은 역공 구조입니다. 17수 C7 이후는 제한된 연속 공격 증명에서 백의 합법 응수가 모두 패배로 배제됩니다. 새 기보 버튼은 추가하지 않습니다.

v5.10은 22수 백 기보를 재현합니다. 21수 흑 E9 뒤 E10은 흑의 5목 승리점이지만 백의 3×3 금수이므로 마지막 22수에 승리 수는 없습니다. 더 이른 18수 백 C8은 흑 E7 준비 수 뒤 강제패배 증명으로 배제합니다. 25초 분석은 빠른 상위 후보의 직접 강제승과 조용한 준비 수를 심층 탐색 전에 검사합니다. 이 판에서 백의 강제승 수는 아직 증명되지 않았으며, 제한 탐색의 대안을 필승으로 표시하지 않습니다. 새 기보 버튼은 추가하지 않습니다.

v5.10.1은 E10 이후 대안 14수 F11, 흑 G8 수순에서 분석이 끝나도 `다음 한 수`가 비던 문제를 고칩니다. 합법 수가 남아 있으면 검증되지 않은 후보라도 명확한 경고와 함께 표시합니다. 이는 필승 수 또는 안전한 방어가 증명됐다는 뜻이 아닙니다.

v5.12.1은 v5.12의 전체 패배 확정을 철회합니다. F6 뒤 흑 G10의 모든 합법 방어 반증은 재검증됐지만, F10 뒤 흑 F5의 제안 수순에는 아직 반박하지 못한 H11 분기가 있습니다. 따라서 F10은 안전하거나 이기는 수라는 뜻도, 확정 패배라는 뜻도 아닙니다. 새 게임에서는 검증된 10.H5·12.F6 반증을 적용하며 기존 전체 패배 캐시로 분석을 조기 종료하지 않습니다. 10.H5 반증은 회전·반전·색 교환과 역분석 API에도 적용됩니다. reports/f10-proof-audit.json과 회귀 테스트로 미완성 증명 채택을 방지합니다.


현재 통합 화면은 15×15 판입니다. 모든 추천은 제한 탐색이며 필승·무패 보장이 아닙니다. 강제패배가 확인되어도 합법 수가 있으면 계속 둘 수 있는 후보를 표시합니다. 이미 5목이 완성되었거나 합법 수가 없으면 추천하지 않습니다. 사진은 로컬 참고용이며 자동 돌 인식은 하지 않습니다.

## 규칙과 저장 호환성

- 정확히 5목만 승리합니다. 6목 이상은 합법이지만 승리가 아닙니다. 4·4는 허용합니다.
- 열린 3을 서로 다른 두 방향에 동시에 만드는 수는 양쪽 모두 금지합니다. 중간이 빈 3도 포함합니다.
- 모든 새 게임과 가져온 기보는 **정확한 5목 우선(숲속 기존 규칙)**을 사용합니다. 이전 규칙 필드는 이 규칙으로 통일하며, 착수 기록은 유지합니다.
- 새 게임은 시간 제한 없음이 기본입니다. 40초 시계를 켜면 초과 시 PASS하며 잘못된 착수는 시계를 초기화하지 않습니다.
- 기존 숲속 저장 키 `forest-omok-v1`과 JSON 형식을 유지합니다. 저장된 기존 기보의 좌표를 뒤집지 않습니다.
- 파일 경로·브라우저가 달라지면 이전 브라우저 저장소를 자동으로 읽을 수 없습니다. 기존 앱에서 **기록 내보내기** 후 통합판에서 **가져오기**를 사용하세요.
- 텍스트 예: `1. 백 H8 · 2. 흑 G9`. 슬라임·버섯 이름과 `PASS`도 가능합니다. 가져오기 전에 차례·중복·금수·종료 이후 착수를 검사합니다.

## 개발 및 검증

Node.js 20 이상, 외부 패키지 설치 없이 실행합니다.

```sh
npm run build
npm test
```

- `src/reader-engine.js`: 빠른 평가·금수·탐색
- `src/forest-engine.js`: 심층 위협 검사와 복기 도구
- `src/unified-engine.js`: 규칙 통일·시간 배분·결과 및 수순 검증
- `src/app.js`, `src/unified-app.js`, `src/template.html`: 통합 화면 및 저장
- `test/reader`: 수읽기 원본의 60개 회귀 시나리오
- `test/unified.cjs`: 규칙 일치, 기존 기보, 필수 방어, 진행 결과, 시간 상한, 심층 분석, 가져오기, 오프라인 패키징 검사
- `tools/prove-loss.cjs`: 오프라인 강제승 연구 도구. 예: `node tools/prove-loss.cjs "H8 G7 G6 H6 F8 I7 E8 G8 F7 D9 F9" 5 180 "" white black-first "" wide`. `proof`가 있으면 모든 합법 응수를 검사한 수순이고, `proof:null`은 표시된 깊이·후보 범위에서 승리를 찾지 못했다는 뜻입니다. `searchComplete:false`는 시간 초과 또는 내부 위협 검사 미완료를 뜻합니다. 어느 경우에도 대국 전체의 승패 판정으로 확대하지 않습니다.

`build.cjs`가 두 실행 경로를 같은 내용으로 생성합니다. 생성된 HTML을 직접 수정하지 마세요.

`omok-reader` 루트에 남아 있는 이전 버전의 개발 파일은 보관 자료입니다. 통합판은 위의 `src/`와 `build.cjs`를 사용합니다.
# 패배 기보 역분석 API

연구 세션의 `counterVcfPruning:true`는 후보 착수 뒤 상대 차례에 최대 20ms의 연속 4 반증을 먼저 검사합니다. 증명이 나온 후보만 제외하며, 미완료 반증은 원래 탐색으로 돌아갑니다. `auditCounterPrunes:true`로 제외한 각 국면의 독립 검증 입력을 함께 받을 수 있습니다. 특정 J6 검사에서 이전 725초 미완료 범위가 1,185ms에 완료됐고 제외 반증 334개 모두 독립 검증을 통과했습니다. 브라우저 전체 분석 속도의 비교가 아닙니다. 검증: `node test/proof-counter-vcf.cjs`. 기본값은 꺼짐입니다.

연구 세션의 `threeExtensions:true`는 합법적인 열린 3 착수에도 기존 추가 탐색 예산을 사용합니다. 상대 응수를 특정 방어점으로 제한하지 않고 모든 합법 응수를 검사하므로, 열린 3 자체를 승리나 강제 응수로 간주하지 않습니다. 4목·필수 방어와 공유하는 `extensions` 한도 내에서만 작동하며 기본값은 꺼짐입니다. 준비 수 한도에서 놓쳤던 시험 공격의 상대 응수 214개를 독립 검증했습니다. 실제 백 승리 대안이 입증됐다는 뜻은 아닙니다. 검증: `node test/proof-three-extensions.cjs`.

내부 연속 4 검사의 시간 상한에 걸리면 `incompleteVcf`에 정확한 수순과 남은 탐색 예산을 기록합니다. 선택 옵션 `retryIncompleteVcf:true`는 800ms 내부 상한에 걸린 국면만 1,600ms 상한으로 한 번 더 검사하며, 각 호출은 현재 구간의 남은 시간 이내로 제한됩니다. 두 번째 검사도 미완료면 여전히 미확정입니다. 기본값은 꺼짐이며 브라우저 분석 시간은 바꾸지 않습니다. 검증: `node test/proof-incomplete-path.cjs`, `node test/proof-vcf-retry.cjs`.

연구 세션의 `forcingHints:true`는 최근 같은 색의 연속 4 증명 최대 4개를 탐색 힌트로 재사용합니다. 현재 판에서 각 착수의 합법성, 상대 즉시 승리, 실제 강제 방어와 승리점을 다시 검증한 경우에만 증명을 반환합니다. 실패한 힌트는 원래 탐색으로 돌아가며 패배나 승리 없음의 근거가 아닙니다. 힌트 검사는 예산의 10%와 20ms 중 작은 값 이내에서 시작하며, 원래 탐색에는 남은 시간을 전달합니다. 기본값은 꺼짐입니다. 검증: `node test/forcing-hints.cjs`.

독립 증명 검증기의 실패 결과에는 `variation`이 포함됩니다. 입력 prefix 이후 실패한 공격/방어 수순이며, 마지막 좌표만으로 다른 분기를 혼동하지 않도록 제공합니다. 미해결 분기는 상대의 안전 증명이 아닙니다. 검증: `node test/proof-failure-path.cjs`.

연구용 세션은 상대의 즉시 승리를 남기는 후보를 정적 평가와 응수 분기 전에 제외합니다. 실제 후보 착수 후 기존 규칙으로 상대 승리 수의 합법성과 정확한 5목을 재검사하며, 내 즉시 승리는 먼저 인정합니다. `immediatePruning:false`로 비교 실행할 수 있습니다. 검증: `node test/proof-immediate-pruning.cjs`. 브라우저 엔진 변경은 아닙니다.

연구용 선택 기능 `--forcing-extensions --defense-extensions`는 상대의 유일한 즉시 승리점을 막는 합법 수에도 같은 유한 확장 예산을 사용합니다. 준비 수 깊이를 유지하지만 확장 횟수는 1회 차감하며, 상대의 모든 합법 응수 검사는 유지합니다. 세션 API는 `forcedDefenseExtensions:true`로 활성화합니다. 기본값은 꺼짐이며 브라우저 추천에는 적용하지 않았습니다. 검증: `node test/defense-extensions.cjs`.

18.C8와 20.G9·G11의 독립 검증된 반증도 새 게임의 동일 국면 및 대칭·색 교환에서 제외합니다. 역분석의 20.G9는 LEVEL 0입니다. 이는 검증된 패배 수의 제외이며 백의 승리 대안 증명은 아닙니다.

v5.12.4는 모든 새 게임에서 연속 4 공격의 필요조건을 먼저 검사합니다. 상대 돌이 없는 연속 5칸 안에 내 돌 3개가 전혀 없으면 현재 수부터 연속 4를 시작할 수 없으므로 불필요한 상세 검사를 생략합니다. 금수·정확한 5목 판정은 기존 코드를 그대로 사용합니다. 초기 국면 3개의 VCF 검사 300회에서 일반 실행 112.46→12.55ms, VM 실행 123.20→13.01ms를 측정했습니다. 전체 분석 속도가 같은 비율로 향상된다는 뜻은 아닙니다. 검증: `npm run test:vcf-prefilter`, 측정: `node tools/bench-vcf-prefilter.cjs`.

오프라인 탐색을 중단 지점부터 이어 읽으려면 `node tools/run-proof-session.cjs reports/sixth-i5-session-spec.json reports/sixth-i5-session-result.json`을 실행하고 `run 25000`을 입력합니다. 한 구간은 최대 25초이며, 프로세스가 살아 있는 동안 탐색 스택과 완료된 캐시를 유지합니다. `quit`으로 종료합니다. 결과 JSON은 관찰 기록이며 종료된 프로세스를 복구하는 파일은 아닙니다. `done:false` 결과에는 승리 증명을 반환하지 않습니다. 검증: `npm run test:proof-session`. 이 도구는 브라우저의 실제 게임 분석과 별도입니다.

연구용 `prove-loss.cjs`는 게임 엔진의 독립 검증된 패배 수를 탐색에서 제외하고 `rootChecks`에 후보별 진행 상태와 증명이 막힌 상대 응수를 출력합니다. `unproved`는 상대 승리 증명이 아니며, `incomplete`는 해당 후보조차 검사 완료되지 않았다는 뜻입니다. 이 기록으로 동일한 전체 탐색의 반복을 피할 수 있습니다.

연구용 루트 응수의 전술 점수가 같으면 기존 평가 함수를 보조 점수로 사용합니다. 후보 순서만 바꾸며 모든 합법 응수 검증은 유지합니다. 첫 번째 미해결 응수가 전체 게임에서 최선인 응수라고 주장하지 않습니다.

`--root-moves=F9,G8`은 지정한 첫 수만 검사합니다. 이후 상대 응수는 제한하지 않습니다. 출력의 `rootMoveScope`가 검사 범위를 명시하며, `searchComplete:true`도 그 첫 수 목록에 한정됩니다. 미완료 후보를 분리해 검사할 때 사용하고, 이를 전체 국면의 승패 증명으로 해석하지 않습니다. `npm run test:root-selection`으로 선택 밖의 승리 수가 결과에 섞이지 않는지와 불법 좌표 처리를 검사합니다.

오프라인 증명 탐색의 선택 옵션 `--forcing-extensions`는 강제 4 교환을 준비 수 깊이와 분리해 최대 8회 추가 검사합니다. 예: `node tools/prove-loss.cjs "H8 G7 G6 H6 F8 I5 G8" 2 25 "" white black-first "" wide --forcing-extensions`. 모든 방어 응수와 금수 검사를 유지하며, 시간 초과는 증명으로 취급하지 않습니다. 검증: `npm run test:forcing-extensions`. 실제 게임의 분석 시간이나 기본 탐색은 변경하지 않습니다.

v5.12.3은 실제 6.I7 뒤 흑 E8의 강제승을 모든 합법 응수 증명으로 확인했습니다. 새 게임의 같은 국면·회전·반전·색 교환에서 I7을 제외하고, 분석 중 임시 후보에도 같은 제외 규칙을 적용합니다. 기존 12.F10의 미완성 G10 증명 대신 완성된 D7 분기 증명을 적용했습니다. 백 승리 대안은 아직 증명되지 않았습니다. 증명 재현: `npm run verify:opening` (오프라인 검증, 각 배치 최대 25초).

v5.12.2는 16.C6 대안을 흑 E6의 모든 응수 반증으로 제외합니다. 독립 증명은 `reports/c6-loss-certificate.json`, 후반 합법 후보 전수검사는 `tools/screen-replay.cjs`와 `reports/later-root-screen.json`에 있습니다. 새 게임의 동일 국면과 대칭·색 교환에도 반영합니다. G10이 안전하거나 승리한다는 증명은 아닙니다.

기존 게임 규칙과 보드 엔진을 재사용하는 Node API입니다. UI에 새 복기 버튼을 추가하지 않습니다.

```js
const {analyze_game}=require('./src/historical-analysis.cjs');
const moves='H8 G7 G6 H6 F8 I7 E8 G8 F7 D9 F9 F10 F5 F6 D7 G10 E6 C8 E7 E5 E9 B7'.split(' ');
const result=await analyze_game(moves,'white','deep25',{rules:{fivePriority:true}});
console.log(result);
```

모드는 `fast`(0.9초), `compare`(3초), `precise`/`auto`(8초), `deep15`(15초), `deep25`(25초)입니다. 숫자 밀리초도 받습니다. 전체 기보의 분석 상한이며, 끝나지 않은 위치는 `timeout`으로 표시합니다. `LEVEL 0`은 해당 착수 뒤 상대의 강제승이 증명됐거나 기존 엔진에 이미 검증된 반증이 있는 경우, `LEVEL 1`은 그 증명이 없지만 전체 무패가 확인되지 않은 경우, `LEVEL 4`는 상대의 합법 대응까지 검사한 강제승인 경우에만 사용합니다. 중간 등급은 근거가 확보되기 전까지 표시하지 않습니다.

독립 국면만 Worker에 분배합니다. 고사양 장치에서도 짧은 런타임 측정에서 처리량이 25% 이상 늘어난 경우에만 최대 2개를 쓰며, 다른 앱을 위해 CPU를 남깁니다. `opts.load`를 제공하면 높은 부하에서 1개로 줄이고, 장치 정보가 없으면 1개로 실행합니다. 브라우저에서 분석 Worker는 선택 시간 뒤 강제 종료되고 마지막 완료 깊이의 결과를 유지합니다.

전후 비교: `node tools/bench-history.cjs 900 3000 8000 15000 25000`. 기존 `HEAD`와 작업 중 소스의 같은 10수 직전 판을 비교합니다. 성능 수치는 장치 부하에 따라 달라지며, 심층 경로에는 추가 위협 검사가 포함됩니다.
## 역분석 시간 종료 시 결과 보존

`analyze_game`의 Worker는 후보 하나의 평가가 끝날 때마다 완료된 후보 목록을 전달한다. 상한에 도달하면 Worker를 종료하고 마지막 목록을 `timeout: true, complete: false`로 반환한다. 아직 평가 중인 후보는 포함하지 않는다. `complete`는 후보 순회를 끝냈다는 뜻이며, 전체 승패 증명이나 모든 탐색 깊이의 완료를 뜻하지 않는다. 후보의 LEVEL과 증명 범위는 따로 확인해야 한다.

`test/historical-progress.cjs`에서 Worker가 중간 결과를 보낸 뒤 멈추는 상황을 재현했다. 이전 경로는 후보를 모두 버렸지만, 수정 경로는 완료된 한 후보와 완료 깊이를 보존한다. 최종 메시지 정상 처리와 시간 제한도 검사한다. 기존 historical 회귀 검사도 통과했다.

실제 22수 기보의 단일 Worker 재측정은 `reports/historical-anytime-verification.json`에 있다. deep15는 4,726ms/깊이4/86,567노드, deep25는 6,190ms/깊이5/137,956노드에 종료됐다. 제한보다 일찍 끝난 것이며 25초를 모두 사용한 탐색이라는 뜻은 아니다. 수정 전후 속도 향상 수치로 해석하지 않는다. 두 실행에서 10.F9와 20.G9는 모두 LEVEL 0이었다. 이번 최고 대안은 LEVEL 1이며 LEVEL 2 이상 대안은 아직 검증되지 않았다.

이 수정은 재사용 역분석 API에 적용된다. 브라우저 착수 엔진/오프라인 HTML/규칙/UI는 변경하지 않았다. 따라서 이번 변경만으로 새 게임의 승리 전략이 개선됐다고 주장하지 않는다.

이번 수정 후 `npm test` 전체 실행이 종료 코드 0으로 통과했다. Reader 60개, Unified 35개 시나리오, historical, historical-progress, proof-certificate, root-screen, known-refutations(128개 대칭/색 교환), VCF prefilter를 포함한다. 과거 부분 실행 기록과 달리 이번 실행은 전체 통과다.

## v5.12.5 — 제한시간 분석의 안정성 검증

사용자 실행본은 기존 `outputs/omok.html` 하나다. 자동 조기 종료는 연속 3개 완료 깊이의 추천, PV 앞 3수, 상위 후보 순위, 평가와 점수 격차가 함께 안정됐을 때 허용한다. 미완료·정보 부족·유한 깊이의 높은 승패 평가만으로 안정 종료하거나 승리를 선언하지 않는다.

25초 모드의 일반 조기 종료와 1 Worker 정책은 유지한다. 유한 깊이에서 매우 높은 승리 평가가 나온 최종 후보에만 최대 1.5초의 기존 상대 응수 검사를 추가한다. 기존 엔진이 상대의 모든 합법 방어를 강제패배로 판정한 경우에만 검증된 승리로 표시한다. 추가 검사가 미완료이거나 점수만 높으면 미증명을 유지한다. 규칙과 기존 PROVEN_LOSS 제외 정책은 변경하지 않았다.

측정·채택·기각 결과: [성능 후속 검증 보고서](reports/performance/phase2-results.md). 이 변경을 F7/J4의 새로운 강제승·무패 증명으로 해석하면 안 된다.
